## 0. 结论

功能链路全部跑通：DNS 记录改/删、SSH 公钥增改删、IP 直连→Tunnel→删除→HTTPS 域名重加、面板启停 Caddy + 三个站点发布与改端口、WireGuard 接口/Peer/Peer 应用发布、端口转发 SSH 全部实测成功。

但交互层问题集中在四类：

1. **状态不同步**：操作成功（Toast/后端已生效）后，列表/抽屉仍显示旧状态或“待应用”，必须刷新或关闭重开。
2. **同一件事多套文案/多套入口**：保存/保存并生效/应用配置混用；空态与页头重复主按钮；抽屉上再盖确认框。
3. **信息过载**：一个 480px 抽屉里塞 3 步说明 + 选项 + 端口要求 + 覆盖说明 + 命令 + 事后提示；DNS/公钥/Tunnel 页每页 3–5 段长帮助。
4. **关键能力缺口/死路**：DNS 记录不能新增；ACME 依赖 cron 但安装器不装也不提示；实时刷新停止后没有“刷新一次”按钮；Caddy/WG 应用失败只给技术日志，没有修复入口。

## 3. P1：逻辑与门控

1. **离线节点空态按钮仍可点**：站点页页头“添加站点”已禁用并给原因，空态里的“添加站点”却 `disabled=false`，点击可打开抽屉。离线时写入口应全部禁用且理由一致。
2. **DNS 记录不能新增**：只有编辑/删除；添加节点时提示“只选用已有记录，不在此新建”。要上域名必须先去 Cloudflare 手工建记录，面板内形成死路。
3. **帮助文案与行为矛盾**：记录列表下方写“只读核对…不会修改 Cloudflare”，但每行有“编辑/删除”，且确实会改。
4. **ACME 安装依赖 cron 但不自愈**：干净 Debian 上 `install.sh --acme` 报“acme.sh 未安装到预期路径（/root/.acme.sh/acme.sh）”；手动 `apt install cron` 后重跑才成功。安装器应检测 cron 缺失并提示/安装，或 acme.sh 加 `--force` 跳过。
5. **WG 应用死路**：残留 `wg-quick@khc0` 单元（active 但 khc0 不存在）导致应用失败“WireGuard 服务已运行，但接口 khc0 不存在”，只给 journalctl 提示，没有“清理/修复”动作；用户只能 SSH。
6. **Peer 应用端口变化不联动站点**：Peer 应用 80→443 后，已发布站点仍指 `10.99.0.2:80`，外网 502；站点表仍“已同步/健康不可用”。建议 Peer 抽屉里维护“已发布站点”关系，或在站点上游检测到 502 时提示。
7. **站点健康状态误报**：三个站点外网均 200，表格“健康状态”全部“不可用”；健康检查与实际访问口径不一致。
8. **实时刷新停止后无恢复入口**：页面显示“已停止自动刷新 · 数据截至 15:32”，但全页没有“刷新一次”按钮（page-specs 要求有），只能刷新浏览器。
9. **L3 删除确认缺名称**：删除域名节点时正文显示“输入节点名 ”（名称缺失），IP 节点时正常；同一组件两种表现。
10. **Tunnel 模式 443 与 Caddy 的边界未说明**：域名接入 Agent 占 443，站点端口如果也选 443 会冲突；表单只给“常用 443/8443/80”，没有占用提示。
11. **TLS 关闭说明错误**：“关闭只监听 80”与实际（监听配置的 2083/8443）不符。
12. **上游端口 443 的 scheme 不可表达**：Caddy 自动把 443 当 HTTPS，面板没有 `http://` 选项；当 Peer 应用在 443 跑明文 HTTP 时无法配置（本次实测报“Client sent an HTTP request to an HTTPS server.”）。

## 4. P1：前后不一致与多入口

1. **抽屉上再盖 Dialog**：Caddy“启动 Caddy”在服务抽屉内直接弹确认框；端口转发“保存并生效”在添加转发抽屉上再弹“应用转发配置？”，同时抽屉仍在。违反 ui-guidelines §8.3。
2. **保存按钮三套**：`保存` / `保存并生效` / 确认框里的 `应用配置` / 转发确认里的 `保存并生效`。同一动作在不同层文案不同，用户不知道差异。
3. **空态 + 页头双主按钮**：添加站点、添加 Peer、添加公钥、添加隧道均同时出现两个同名 primary。
4. **状态词混用**：`待应用` / `待上线后生效` / `需手工处理` / `不可用` / `未知` 在同一产品内表达相近含义；术语表只有 `未生效/待生效`。
5. **“控制面不可达”用错对象**：只有节点离线时，节点页横幅写“控制面不可达 / 当前无法向 Hub 下发操作”，用户会以为面板坏了；应写“节点不可达”。
6. **重复描述**：站点页离线提示标题“节点不可达”+描述“节点不可达，暂时不能执行该操作”；概况“服务异常”与“服务 1 个异常”重复。
7. **同一对象三种呈现**：证书库在 `/settings?tab=certs` 是 Card+表，在站点页是只读表，在节点概况是摘要；标题“证书库/域名与证书”并存。
8. **“应用状态”在 IP 模式显示“已安装/未运行”，Tunnel 模式变“未知”**：同一节点同一应用，因接入方式不同换词，未解释。

## 5. P1：展示问题

1. **表格 7 列**：站点表 = 域名/类型/端口/上游/TLS/健康/同步，超过规范 ≤6；1440 以下密度偏高。
2. **数字粘连**：节点概况“站点 22 启用”（应为“2 个站点 · 2 启用”）、“负载 0.3%内存 143 MiB”（缺分隔）。
3. **Caddyfile 路径断词**：抽屉里显示 `/etc/cad` + `dy/Caddyfile`，像损坏；长 mono 值应整体截断 + title 查看。
4. **外部配置噪声**：站点页“外部配置（未托管）”固定出现一行 `— 静态 — 关闭 TLS 第 11–23 行 需手工处理`，无实际可操作信息。
5. **加载态像空态**：表格首屏 5 行空白单元格（Skeleton），没有“加载中”，1–2 秒内看起来像数据丢失；节点列表曾出现“还没有节点”闪一下。
6. **结果页过长**：新建节点后，480px 抽屉依次塞入令牌、3 步说明、安装方式、Caddy 选项、端口要求、覆盖说明、安装命令、事后提示；安装命令在首屏之外，用户需长滚动。
7. **健康状态列无原因**：只显示“不可用/未知”，没有 tooltip 或重试入口。
8. **节点概况证书文案误导**：Agent 已有 ACME 证书，但页面写“证书状态：未签发（该域名未建站点…）”，说的是 Caddy 站点证书，未区分“Agent 证书 / 站点证书”。

## 6. P2：操作过于麻烦

1. **DNS 记录管理路径过深**：设置→域名→打开凭据→展开 Zone→行内编辑→行内保存→还要区分“保存记录/保存凭据”两套按钮；且不能新增。
2. **看到一个真实状态需要“关闭重开/刷新页面”**：Caddy 服务、内网穿透 Peer、站点同步、端口转发均如此。
3. **创建节点出口过多**：结果页同时有“我已完成安装 / 去节点设置 / 完成”，语义重叠。
4. **两套保存 + 一次确认**：站点/转发/接口/Peer 表单都是“保存 / 保存并生效 + 二次确认”，一次配置要 3 次点击。
5. **实时刷新恢复**：必须整页刷新（无“刷新一次”）。
6. **删除节点确认文案过长**：4 段说明 + 勾选 + 输入名称；L3 可以严，但建议折叠“为什么/卸载脚本”说明。

## 7. P2：多余提示与文案

1. 域名页：页头“最小权限 Token”长横幅 + 名称帮助 + Token 帮助 + Zone 帮助 + 绑定 Zone 帮助（5 段）。
2. 公钥页：“只存公钥”横幅 + 名称帮助 + 公钥帮助；空态再写一句。
3. 隧道页：Cloudflare Tunnel 横幅 + 名称/域名/端口/Token 四段帮助。
4. 站点/转发表单底部重复“保存并生效后会创建配置并重载 Caddy”“socat 未安装请先安装”等说明，且在已成功后仍显示。
5. 安装结果页“重新安装会覆盖什么？”整段解释，建议折叠为“高级说明”。
6. “这是明文 HTTP 入口…” + “未勾选时无法保存”重复表达同一限制。
7. 实时观测错误把 `CORS`、`/_live`、`KHC_LIVE_ORIGINS` 等内部术语直接暴露给用户。

## 8. 建议修复顺序

### 第一批（状态一致性，收益最大）

1. 统一“变更后失效 query”：节点创建/探活、SSH 公钥增删、站点 apply、转发 apply、Caddy start/reload 成功后就地刷新。
2. 站点/转发/Peer 的 apply 任务完成后主动 refetch，不要只靠 10s 快照或整页刷新。
3. 修复新建节点行“探测中…”不更新：`useHubProbe` 把新节点加入 probe 结果或 probe 后强制刷新。
4. 统一状态源：`HubChannelsProvider` 与 `/state` 快照口径合并，避免概况在线、内网穿透离线。

### 第二批（交互范式）

5. 去掉“抽屉上盖确认框”：Caddy 启动、转发 apply 改为“关闭抽屉 → 页面级 ConfirmAction”。
6. 每个表单只保留一个保存动作：要么“保存并生效”，要么“保存”+页面横幅“应用配置”，二选一。
7. 空态与页头主按钮二选一；离线时两处同时禁用并给同一原因。
8. 实时刷新停止时补 [刷新一次]。

### 第三批（能力与文案）

9. 补 DNS 记录“新增”入口（可复用行内表单）。
10. ACME 安装检测 cron；缺失时给明确命令或自动安装。
11. 站点健康检查改用与真实访问一致的口径，或在“不可用”上给原因/重试。
12. Peer 应用端口变化时提示“已发布站点仍指向旧端口”，并提供一键改上游。
13. 收敛术语：`待应用/待上线后生效` → `待生效`；`控制面不可达` → `节点不可达`；`应用配置` → 统一为 `应用更改` 或 `保存并生效`。
14. 站点表减到 ≤6 列（健康状态并入同步或行详情）。
15. 节点概况修复数字粘连与“Agent 证书/站点证书”区分。

- Tunnel 只验证了配置层（无真实 Cloudflare Tunnel Token），未验证 cloudflared 真实连通；状态按预期离线。
- 域名 + HTTPS 首次安装因测试机缺 cron 失败，手动补 cron 后通过；这不是产品代码缺陷的唯一路径，但安装器提示不足。
- 端口 2084 外网不可达是云防火墙未放行，非产品问题；已改用 8443 验证。
- 未做 390/深色/键盘走查；本次只做交互与逻辑。
