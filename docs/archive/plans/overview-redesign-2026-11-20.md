## 1. 背景（主人 2026-11-20 的要求）

1. 首页是「总览」：不放主机指标，只放首页接口已有内容；卡片一行两张，核心是**应用在线 / 总数、Peer 在线 / 总数**。
2. VM 到期只记一个固定日期，不自动顺延。
3. 域名、Tunnel、IP 直连三种接入都要有合理显示；IP 直连节点也可以有应用证书。
4. **功能开启才显示，界面不许出现「0 个」。**
5. **应用 = 经 Caddy 反代出来的服务**（如 hermes）；没经过 Caddy 的自装软件（如 sing-box）放 VM 详情里维护。
6. 应用在线看 Caddy 报的状态，**端口 down 就算异常**。
7. 「站点」叫法易误解，改叫「应用」。
8. 首页与 VM 详情口径统一；VM 详情（顶部 Tab）一起重组。
9. **数据尽量一个接口查出来，实在不行再加接口。**

原型：`overview-redesign-2026-11-20/home.png`（首页）、`overview-redesign-2026-11-20/hub-overview.png`（VM 概况）。

## 2. 统一规则（全站）

| 规则 | 内容 |
|---|---|
| R1 术语 | **应用**：已启用的 Caddy 反代（`kind=proxy`），一条算一个。**组件**：Caddy、WireGuard、转发、node-exporter 等内置项。**服务**：没经过 Caddy 的自装软件（如 sing-box），只在 VM「主机」Tab 维护。静态站点与跳转不算应用。 |
| R2 开启才显示 | 组件未装或产物为 0 时，对应统计格、摘要、分组、KPI 一律不出现。界面不出现「0」「0 / 0」「—」「暂无」。 |
| R3 全部离线 | 已开启但全部离线时写「N 个离线」（红），不写「0 / N」。 |
| R4 异常即待办 | 应用异常、Peer 离线、证书 ≤14 天、VM ≤14 天到期，统一进入「需要处理」，点击直达。为 0 时整格隐藏。 |
| R5 接入方式 | 连接行 = 接入方式 chip + 地址 + 接入安全性。域名：「HTTPS · 接入证书剩 N 天」；Tunnel：「由 Cloudflare 边缘托管」；IP 直连：灰色「HTTP 明文 · 无接入证书」，是主动选择，不算异常。 |
| R6 证书 | 应用证书与接入证书分开。统计格「证书」= 证书库中 `sourceNodeId` 为本节点或覆盖本节点域名的证书数，附最近到期天数。只统计证书库，Caddy 自动签发的不计（文案注明）。 |

### 2.1 应用在线判定（不改 Agent）

`caddy_site._probe_url` 经 Caddy 对每个启用站点做 HEAD/GET：`<400` 记 `ok`，任何 HTTP 错误码记 `warn`，连接失败记 `down`，自签证书记 `warn`。**上游端口 down 时 Caddy 自己仍在，会回 502，被记成 `warn`**，因此面板必须按状态码自行判定：

| siteHealth | 面板判定 |
|---|---|
| `ok`；`warn` 且 status 为 4xx；`warn` 且为自签证书 | 在线 |
| `warn` 且 status 为 502 / 503 / 504；`down` | 异常（进「需要处理」） |
| `unknown`（未探测、超预算） | 未知，不计入在线也不计入异常 |

判定函数做成纯函数并单测，概览与 VM 内共用同一份。

## 3. 首页

- **KPI 四格**：VM 在线、应用在线、Peer 在线、需要处理（按 R2，没有应用或 Peer 的格不显示，待办为 0 隐藏）。
- **VM 卡片（一行两张）**三层：名称 + 到期 chip（配置才显示，≤14 天标黄）+ 在线点；连接行（R5）；统计格 应用在线 / Peer 在线 / 转发 / 证书，按 R2 只显示有的，靠左排列。有待办描黄边。

## 4. VM 详情：顶部 Tab 重组（6 → 5）

现状：概况、对外服务、站点、内网穿透、主机运维、节点设置。「对外服务」是站点 + 转发 + Peer 的只读汇总，和「站点」「内网穿透」重复，概况里的对外服务卡又重复一遍。

| 新 Tab | 内容 | 来自 | 显示条件 |
|---|---|---|---|
| 概况 | §5 | 概况 | 总是 |
| 应用 | Caddy 反代应用列表；分段：静态与跳转、证书（有才显示） | 站点 + 对外服务 | 总是（Caddy 必装；为空时显示「添加第一个应用」引导） |
| 网络 | Peer、转发 | 内网穿透 + 对外服务 | 装了 WireGuard 或有转发规则 |
| 主机 | 受管服务（含 sing-box 等自装服务）、定时任务、密钥、诊断、主机指标详情 | 主机运维 | 总是 |
| 设置 | 接入方式、Agent、组件安装、到期日期 | 节点设置 | 总是 |

- 「对外服务」Tab 取消，`/hubs/:id/services` 改为 302 到应用 Tab；`/hubs/:id/sites` 路由保留（只改显示名），避免书签失效。
- 文案：内置项称「组件」，`/apps/:app` 组件详情路由不变。

## 5. VM 概况页

- **页头**：名称 + 到期 chip；连接行（R5）+ Agent 版本；右侧实时快照时间。在线只在顶栏显示一次（现状重复 3 次），去掉页脚与摘要行（与指标重复）。
- **需要处理条**（R4，含受管服务失败）；为空隐藏。
- **指标四格**：与首页卡片统计格同一口径（应用在线、Peer 在线、转发、证书），按 R2。
- **左卡「应用」**：反代应用（名称、上游、异常标红写状态码），下接「网络」小节（Peer 握手时间、转发规则）；无内容的小节不显示，全空整卡隐藏。
- **右卡「主机」**：CPU / 内存 / 磁盘（10 秒快照）、系统、运行时长、受管服务。主机指标只在 VM 详情出现。

## 6. 接口

### 6.1 VM 概况：新增 `GET /api/v1/nodes/:id/overview`

现状概况页 6 个请求：`/nodes/:id`、`/nodes/:id/state`、WireGuard / Caddy / 转发三份配置、全局 `/certificates`，另加 10 秒快照。

| 选项 | 做法 | 请求数 | 评价 |
|---|---|---|---|
| **A（推荐）** | 新增聚合接口：Worker 读 D1（节点、三份配置摘要、`sourceNodeId` 为本节点或覆盖本节点域名的证书）+ 调一次 Agent `/state`，返回投影（应用判定结果、Peer 在线、转发、受管服务、主机静态信息）。Agent 不可达时 D1 部分照常返回，Agent 部分为 `null` | 1 + 快照 | 满足「一个接口」；离线也能显示配置 |
| B | 不加接口，只把全局证书换成按节点过滤 | 6 + 快照 | 改动小，但没解决请求多 |

快照轮询节奏（10 秒、60 次上限）不同，**保持独立**，不并入。
编辑类页面（应用、网络的抽屉）仍按需取完整配置（含 rev，用于乐观并发），不走聚合接口；切 Tab 时列表先用聚合数据渲染。

### 6.2 首页

| 选项 | 做法 | 请求数 |
|---|---|---|
| **A（推荐）** | 保留 `/nodes`（只读 D1，秒出，离线节点也显示）；`/nodes/probe` 响应新增每节点的应用、Peer 投影与证书匹配结果，去掉 `/certificates` | 2 |

### 6.3 投影放哪里

Worker 在 `apps/api/src/lib/` 新增投影模块（与 `node-summary.ts` 同层），按适配器名提取 `peers{online,total}`、`apps{online,total,issues[]}`（issues 只带名称与状态码）。`routes/nodes.ts` 仍不识别应用名（保持现有约定）。首页 probe 与 VM overview 共用同一模块与 §2.1 判定。备选：Agent 每个适配器报通用 `gauge`（需 Agent 0.6.4，旧 Agent 退化），不推荐。

### 6.4 到期时间

`nodes.expires_at`（迁移 0014），依赖 PR #90 迁移常态化（CI 目前硬编码 0013）。
