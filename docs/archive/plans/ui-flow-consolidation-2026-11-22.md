## 2. 实测 4 条端到端主流程的「真实断点」

| 主流程 | 当前需要跨多少页面/动作 | 实测卡死或反直觉的断点 |
|---|---|---|
| **流程 1：接管新 VM** | 需跳 **3 处**（`/settings?tab=accounts` → `tab=domain` → `/hubs`） | ① `添加节点` 选「域名」时只能选已有记录，**缺少就地新建 A/AAAA 解析与 DoH 检测**（后端接口已有）；② 装完 Agent 验活只看「Agent 在线」，没验证外部访问/DNS 与引导「下一步发布应用」；③ 节点列表/概况无 **Agent 版本过期角标**（`oracle`/`unicom` 停在 `0.6.0` 没人知道，去装清单应用易踩坑）。 |
| **流程 2：发布应用到公网 URL** | 配 Caddy + 查 DNS + 配防火墙 + 测访问，至少跨 **4 处** | ① **Caddy 与防火墙彻底脱节**：`aws-hui-us` 发 `:8779`/推荐 `:8443` 时，宿主防火墙根本没放行，Caddy 却报 `✓ 已同步`，用户打不开不知原因；② **缺乏最终可达性确认**；③ 页内仍存在 2 个发布入口 + 3 张下挂卡片，且「端口转发规则的监听端口（如 `2083 socat`）」混进「本机监听端口」诱导二次反代；④ 非 CF 域名（如 `unicom-hub`）缺明确解析指引。 |
| **流程 3：内网穿透与跨机发布** | 切模式 → 装组件 → 接口设置 → 加 Peer → 发应用，**5–6 步跨 4 页** | ① 未用组网的机器（如 `aws-hui-us`）因初始 `mode=wg` 长期暴露「网络」Tab 与虚警；② **没有「配置未保存」或「无效转发」清理指引**（`unicom-cn-1` 删了 Peer 却残余 socat 到不存在 IP，连累站点 502）；③ 点 Peer「发布为站点」虽预填上游，但未带出「建议走 Hub 域名的 HTTPS」完整闭环。 |
| **流程 4：月用 10 次的巡检与运维** | 概览 → 节点页多处查找 | ① 概览「需要处理」有 `llproxy 不可达`、`peer-app-sg HTTP 502`，点击只跳去 `/sites` 列表，没有「故障定位卡」（例如标注：是本机进程挂了、Peer 离线还是端口未放行）；② `/settings` 默认首 Tab 是「证书库」，但无「账号/域名」引导顺序，且 0 项的资源（隧道/公钥）仍占顶层视野。 |

## 3. 方案对比与推荐：用「4 条端到端主线」代替按表平铺

| 方案 | 做法 | 优点 | 缺点 |
|---|---|---|---|
| **A（推荐）** | **「纯前端流程编排 + 减法收敛」优先，仅 P4 按需补 1 个只读连通性接口** | P1–P3 **100% 在 `apps/web/` 完成**，零 `agent/`/`apps/api/`/D1 迁移风险；立刻把现有 API 能力串成闭环 | 浏览器无法绕过 CORS/自签直接测非 443 端口「公网真通」全貌（浏览器侧受限，需 P4 决定是否由 Worker 轻量探测） |
| **B** | 重写导航层级与全部后端聚合接口 | 一步到位 | 违反 `AGENTS.md` §3「核心冻结、不新增导航层级」红线，周期长 |

    F1["流程1: 添加/接入新VM"] -->|"已有CF账号时就地建解析 + DoH检测 + 安装完直达"| F2["流程2: 应用上线 (站点 + 放行 + 验活)"]

    F3 --> F2

### 3.1 页面与卡片收敛清单（减法优先，守住六类页面与单抽屉原则）

1. **全局 `/settings` 重排认知顺序，不改导航层级**：
   - 分段顺序改为按使用前置依赖排序：`域名管理（含账号）` → `证书库` → `应用管理` → `隧道` → `SSH 公钥`（或账号与域名保留 6 Tab 但顺序前置、首次无账号时「证书/域名」均展示单一主引导；已有账号时「添加节点」不再强迫跳出）。
2. **`/hubs`（添加节点抽屉）接通 DNS 闭环**：
   - `AccessForm` 选「域名（HTTPS）」时，直接在域名旁增加可选「就地新建 A/AAAA 解析 + 检测生效（调现有 `POST /cf-dns/records/:zoneId` & `/resolve-check`）」，不再断在半路。
   - 安装命令验活通过后，底部直接给 **[去发布第一个应用 →]** 按钮（带到 `/hubs/:id/sites?wizard=1` 或 `?drawer=site:new`）。
   - 全局 `/hubs` 与节点概况展示 **Agent 可升级提示**（对比 `/agent/releases` 最新版本，一键跳转 `/hubs/:id/settings` 或触发 `POST /nodes/:id/agent/upgrade`）。
3. **`/hubs/:id/sites`（应用页）联动宿主防火墙与过滤规则**：
   - **过滤内部转发端口**：`unpublishedListeningPorts()` 同时过滤已被 `forwards` 占用的端口（已有逻辑要核对 `tcp6 ::` 与 `port` 匹配：`unicom` 的 `:2083 socat` 漏网是因为 `2083` vs `0.0.0.0:2083`），不再误把 socat 转发当未发布业务进程。
   - **抽屉内防火墙联动（核心痛点）**：打开 `SiteDrawer` / `InstallAndPublishDrawer` 且 Node 开启了 host-ops 时，按需读 1 次 `fw.show`：若拟发布的对外端口（如 `:8443` / `:8779`）不在宿主允许列表（且不是 Tunnel 模式），抽屉/应用成功后直接提示「主机防火墙尚未放行 `:8443`」并给 **[一键放行 TCP 8443]** 按钮（直调现有防火墙放行能力，避免写 2 次再跳去 `/ops`）。
   - **主按钮心智唯一，不并列打架**：主操作保留 **[+ 发布应用]**（合并引导：选「从清单安装」直接打开三步向导，或「接入本机/Peer 服务」进 `SiteDrawer`）；监听端口卡片保持空时隐藏、「外部配置」无异常块时可折叠进页底「高级」区，让应用页首屏只见「正在运行的应用列表」。
4. **`/hubs/:id/wireguard`（网络）按实需出现与孤儿告警**：
   - 新节点默认或空 Peer+空转发节点建议 `mode=caddy`（或引导一键切到「Caddy 网关」模式），使纯粹做反代的机器（如 `aws-hui-us`）自动隐藏无用的「网络」Tab 与「公网地址未配置」误报。
   - 当转发规则或 Caddy 站点引用了已不存在的 Peer（如 `unicom-cn-1` 的 `10.99.0.4`），在「网络」及概览「需要处理」明确标出「来源 Peer 已删除/未接入」+ 一键停用/编辑入口。
5. **概览「需要处理」直达诊断原因**：
   - 当站点的上报告警是 `502 / 不可达` 时，点进对应节点「应用」页直接给出内联排查原因条（如「目标 `127.0.0.1:8787` 未监听」或「Peer `sg-nat` 离线」或「宿主防火墙未放行 `:8779`」），而不是让用户自己盲猜。

## 4. 范围与不做

- **严格守住定位**：依然是「每月打开 ~10 次的运维遥控器」，**不新增**常驻心跳、监控图表、第 3 层导航、插件市场或抽屉内叠 Dialog（完全遵守 `AGENTS.md` §1、§3）。
- **核心冻结保护**：P1–P3 **不改动** `agent/`、`packages/contracts/`、`migrations/` 与现有 D1 schema；P4 若决定加「控制面从公网实际发 HTTPS/TCP 探测发布地址」，再按需单独评审 1 个只读接口或复用 `POST /nodes/probe`。

## 5. 分批实施路线（以在 3 台测试机真机跑通为验收）

| 批次 | 范围（仅代码层） | 验收标准（含 3 台机真机实测） | 版本 Bump |
|---|---|---|---|
| **P1：接入与发现闭环** | `apps/web/`（`AccessForm` + `HubsPage` + `OverviewPage` + `hubs` Agent 版本比对） | `/hubs` 添加域名节点可直接新建 A 记录并验解析；安装完直接跳「发布应用」；`oracle`/`unicom` 旧版本 `v0.6.0` 有明确升级入口且可一键完成升级 | 面板 minor（不改 Agent） |
| **P2：发布与防火墙联动** | `apps/web/`（`caddy/` + `hostOps` 防火墙轻量查询/追加规则 + `unpublishedListeningPorts` 过滤修补 + 收叠空闲「外部配置」） | `aws-hui-us` 上把 `python3:9099` 或 `llmproxy` 发布到 `test.16666.cyou:8443` 时，界面识别 `tcp/8443` 未放行并一键追加放行；`unicom` 不再把 `:2083 socat` 列为未发布端口；空外部块收进高级区 | 面板 minor |
| **P3：组网清理与故障直达** | `apps/web/`（`wireguard/` + `OverviewPage` + `/settings` 顺序/空态引导收敛） | 纯反代机器不误显「网络」噪音；`unicom` 孤儿转发与 502 站点、以及 `aws` 未监听 upstream 在「应用/需要处理」直出明确病因，支持就地停用/修复 | 面板 minor |
| **P4（可选）：发布后真实公网可达性探测** | 需先决策：`apps/api/` 新增或扩展只读 HTTP HEAD 探测（通过 CF Worker/DoH 校验 `https://域名:端口` 对外通不通） | 点击「保存并生效」或向导第 3 步完成后，真机实测返回外网访问状态（DNS/TLS/HTTP 状态码）而不只报「Caddy 已加载」 | 面板 minor |
