# 面板 WebSSH 与脚本任务（提案）

> 状态：已否决（2026-11-15，S0 实测后终止） ｜ 最后核验：2026-11-15 ｜ 关联：PR #55、`docs/verification/2026-11-15/webssh-caddy-smoke.md`

> **已否决，不得据此开工。** S0 实测（PR #55，已关闭，分支 `docs/webssh-s0-verification` 保留证据）发现：① 刷新或断网会连同正在跑的脚本一起丢失，ttyd 退出时还会杀掉它自己拉起的 tmux，所以断线接回做不到；② 随机路径就是 root 凭据，Origin 校验实测不生效，完整 URL 还会落进日志；③ Hub 需要持有能登录所有 Peer 的私钥，与 ADR-0007 相悖；④ 要破 AGENTS.md 红线、改冻结核心，ttyd 上游两年多没发版，发行版里的包还挂着未评估的 CVE。面板每月只打开约 10 次，主人本机本来就有 SSH，收益抵不过风险。终端需求回到「本机 SSH 客户端」。

## 1. 背景与主人的决定

主人要的是：

1. **手动安装**：在面板里进入 Hub 或 Peer（VM）的终端，跑第三方一键脚本、回答交互菜单、看到最终输出。
2. **自动安装（以后）**：自研应用由面板直接下发一键脚本并读回结果，不再依赖外部 SSH 客户端。

2026-11-15 讨论的结论：

- 不用 Cloudflare Access 浏览器 SSH：每台机器都要装 `cloudflared`，主人不接受。
- 不用 Worker + Durable Objects 直连 sshd（本提案初稿的路线 A）：终端会话会持续消耗 Workers Free 的 DO 额度，主人不接受。
- **采用路线 C：浏览器直连 Hub，不经过 Worker。** 这条路径和「可信域名」节点的快照通道一样（`live-observation.md` §1）：浏览器经节点域名的 HTTPS（或 Tunnel）→ Caddy → Hub 本机。
- **限制**：只有配置了「域名 + HTTPS」或使用 Tunnel 的 Hub 才能开 WebSSH。IP 直连的节点不开放，界面上显示为不可用并说明原因。Peer 经 Hub 进入，能否使用跟随它的 Hub。

## 2. 组件调研（主人要求：成熟、简单）

| 组件 | 许可证 | 成熟度（2026-11-15 GitHub） | 形态 | 结论 |
|---|---|---|---|---|
| **ttyd** | MIT | 约 1.26 万 star；最新 release 1.7.7；仓库 2026-08 仍有提交 | C 单二进制，自带 xterm.js 网页和 WebSocket | **推荐** |
| gotty（sorenisanerd 分支） | MIT | 约 2.6 千 star，仍在维护 | Go 单二进制，形态同 ttyd | 备选 |
| wetty | MIT | 约 5.5 千 star | Node 应用 | 节点要装 Node，否决 |
| huashengdun/webssh | MIT | 约 5.1 千 star，2025-07 后无提交 | Python tornado + paramiko | 要装 pip 依赖，否决 |
| pyxtermjs | MIT | 约 400 star，2024 年后无提交 | 示例项目 | 否决 |
| sshwifty | AGPL-3.0 | 约 3.1 千 star | Go | 许可证不合适，否决 |

选 ttyd 的理由：

- 一条命令就是一个网页终端：`ttyd [选项] <命令>`。
- 关键选项都现成：`-i` 绑定 unix socket，`-o` 只接受一个客户端、断开即退出，`-W` 允许写入，`-O` 校验 Origin，`-b` 设置反代路径前缀，`-H` 交给反代鉴权。
- 前端用它自带的页面，**面板不引入 xterm.js，也不写 WebSocket 代码**。
- 在节点上属于「按需安装」的模块，和其他模块一样，未安装是中性状态。

## 3. 架构

```
面板 ──取票──▶ Worker ──HMAC──▶ Hub Agent：开会话（返回随机路径）
面板 ──新标签页──▶ https://<Hub 域名>/_term/<随机id>/ ──Caddy──▶ unix socket ──▶ ttyd --once
                                                                         │
                                       Hub：systemd-run 起 bash -l（跳出 Agent 沙箱）
                                       Peer：ssh -tt -i <Hub 专用私钥> <用户>@<Peer WG 地址>
```

1. 面板请求 Worker 开会话。Worker 用节点 token 做 HMAC 签名后调用 Agent 新增的动作 `term.open {target: hub|peerId}`。
2. Agent 通过 `systemd-run` 起一个临时单元，运行
   `ttyd -o -W -O -U <caddy用户>:<caddy组> -i /run/khc/term-<id>.sock -b /_term/<id> <命令>`。
   `<id>` 是 128 位随机数（URL 里用 hex），单元设置 `RuntimeMaxSec`。**`-U` 必填**，理由见 §3.1。
3. Caddy 站点里加一条按会话 id 选择 socket 的路由，由 `caddy_site` 适配器生成（写法与可行性见 §3.1）。注意这与 `liveGateway`（`/_live/*` → 固定 `127.0.0.1:8899`）**不同**：那里是静态单上游，这里是动态多上游。
4. 面板在新标签页打开该地址。`--once` 保证只有第一个连上的人能用，断开后进程退出。60 秒内没人连上，Agent 就结束这个单元。
5. **Peer**：由 Hub 本机的 `ssh` 客户端经 WG 连接 Peer。专用 ed25519 私钥在 Hub 上生成（0600），永远不离开 Hub。公钥需要主人加到 Peer 的 `authorized_keys`；面板只展示公钥，不保存任何私钥。
6. **断线续接**：不做，但必须明确后果与对策。`-o` 是「断开即退出」，浏览器刷新、标签页误关、网络抖动都会**丢掉整个 root shell 和正在跑的脚本**；`RuntimeMaxSec` 又是硬上限，会杀掉长编译/长安装。两者叠加与 §1「跑带交互菜单的一键脚本、看到最终输出」直接冲突。对策：S1 把默认命令定为 `tmux new -A -s khc`（**tmux 列为必需依赖而非可选**，未安装则终端入口不可用并提示），`RuntimeMaxSec` 只作兜底（建议 ≥ 2h）且在单元退出时保留 tmux 会话；S3 的非交互长任务走任务机制，不依赖终端。S0 必须实测「刷新页面后重连能否接回 tmux 且脚本仍在跑」。

### 3.1 前置实测（2026-11-15，联通云测试节点，Caddy 2.6.2）

开 S0 之前先用最小模型验证了两处会决定架构成立与否的假设，**没有安装任何新组件**：临时起两个 unix socket HTTP 后端 + 一个独立临时 Caddy（`admin off`、独立端口 19002/19003、独立配置，不写 `/etc/caddy`、不 reload 生产实例），测完即清理。完整记录见 `docs/verification/2026-11-15/webssh-caddy-smoke.md`。

| 假设 | 结论 | 证据 |
|---|---|---|
| Caddy 能否用路径捕获组把 `/_term/<id>/` 映射到**不同**的 unix socket | **可行**（推翻了「Caddy 不支持动态 unix socket」的初判） | `@term path_regexp term ^/_term/([a-z]{2})/` + `reverse_proxy unix//.../term-{re.term.1}.sock`：`caddy adapt` 通过；运行期 `/_term/aa/` → `SOCKET_aa`、`/_term/bb/` → `SOCKET_bb`，均 200 |
| socket 由 root 创建、Caddy 以 `caddy` 用户运行时能否连上 | **不能连，必须改属主** | 未 `chown` 时 socket 为 `srwxr-xr-x root:root`，Caddy 返回 502，日志 `dial unix ... connect: permission denied`；`chown caddy:caddy` 后同一请求返回 200 |

因此：

- 动态路由采用 `path_regexp` 捕获组 + `{re.*}` 占位符，由 `caddy_site` 渲染。Caddy 文档称「含占位符的上游需带端口」，实测 unix socket 形式在本版本可用，但**S0 必须在目标节点的 Caddy 版本上复验**，并测 `caddy fmt` / `validate` 与 WebSocket Upgrade 是否同样通过（本次只验了普通 HTTP GET）。
- ttyd 命令必须带 `-U` 把 socket 属主设为 Caddy 运行用户；该用户不能写死，复用批次 1（PR #45）已落地的 `_caddy_owner` 探测（`/proc/<pid>` → `systemctl show -p User` → 回退用户名）。`/run/khc/` 目录也要给该用户执行权限。
- **风险等级提升**：动态上游意味着路径里的 id 直接参与 socket 路径拼接。id 必须严格限制为 `[0-9a-f]{32}` 十六进制；`caddy_site` 渲染前要校验，防止路径穿越或注入额外 Caddyfile 指令。S1 必测一项：非法 id 必须被拒绝且不产生任何 socket 路径。

## 4. 设计要点

### 4.1 鉴权（W-2 已定：K1）

| 选项 | 做法 | 优点 | 缺点 |
|---|---|---|---|
| **K1** | 只靠随机路径：128 位随机 id + `--once` + `-O` 校验 Origin + 60 秒内必须连上 | 不改 Agent 的 HTTP 核心，最简单 | 路径在有效期内相当于口令，会进浏览器历史（会话结束即失效） |
| K2 | K1 再加 Caddy `forward_auth` 到 Agent 校验一次性票据 | 多一层防护 | 要改 `agent/khc/http.py`（冻结核心），ttyd 一个页面有多次请求，需要换成 cookie，复杂度明显上升 |

推荐 **K1**。打开 WebSSH 的前提仍然是面板已登录。TOTP 测试期不强制，上线前开启（见 §6）。

**K1 的准确边界（S1 必须按此实现，不能只写「校验 Origin」）**：

- `-O` 只校验 **WebSocket 升级请求**的 Origin，不校验页面本身的 HTTP GET。也就是说随机路径在有效期内是一枚不依赖面板会话的 bearer token：任何拿到 URL 的人无需登录即可打开 root shell。
- URL 会进入浏览器历史、`Referer`、Caddy access log 和运维代理日志。`--once` 与 60 秒窗口只缩短暴露时间，不消除留存。
- 因此 S1 必须同时具备：**① 设置里的 WebSSH 总开关，默认关闭**（沿用上一版 W-6 的决定，改版时遗漏，此处补回）；**② TOTP 未启用时终端入口与终端页顶部常驻警示**「未启用两步验证：面板密码即节点 root」；**③ 面板侧对 `/_term/` 页面下发 `Referrer-Policy: no-referrer` 与 `Cache-Control: no-store`**；**④ Caddy 对 `/_term/*` 关闭 access log 或只记路径前缀**，避免把 bearer URL 完整落盘。
- S0 实测 K1 的暴露面后，若上述④条仍不足，按 W-2 的既定退路升级到 K2（`forward_auth` + cookie），不擅自扩大范围。

### 4.2 脚本任务（批次 S3）

- 不用 ttyd。Agent 用现有任务机制（ADR-0018）执行脚本：Hub 本机用 `systemd-run`，Peer 用 `ssh <peer> bash -s < 脚本`。
- 结果约定：脚本最后输出一行 `KHC_RESULT {json}`。面板解析后，带端口的结果直接接到「发布本机端口」。字段名含 `password`、`secret`、`token` 的值只显示一次，不落库。
- 脚本库（原 R-8）：全局设置里保存「名称 + 命令」，不存凭据。

### 4.3 审计（W-3 已定：只记元数据）

- 默认：D1 `audit` 记录节点、目标、开始和结束时间。
- 可选：沿用 11-13 的 T-A 决定，用 `script` 在节点本地记录输入，文件 0600、保留 7 天。路线 C 下终端在我们自己的进程里，可以做到。

### 4.4 与现有规则的关系

| 规则 | 影响 |
|---|---|
| `AGENTS.md` §1 不做心跳和 WebSocket | 面板和 Worker 不引入 WebSocket。WebSocket 只存在于浏览器和节点上的 ttyd 之间，需在 §1 注明这一例外 |
| `ui-guidelines.md` §9 不引入终端模拟器 | 不受影响：终端页由 ttyd 提供，面板只开新标签页 |
| 面板不与 Hub 保持长连接 | 不受影响：观测通道照旧，终端由主人主动打开、关闭即断 |
| ADR-0007 | **方向性变化，须写进 ADR-0020**：现有 host-ops 的 Peer 公钥是 `restrict,command="sudo -n /usr/local/sbin/khc-host"` **强制命令**，拿不到交互式 shell；WebSSH 要进 shell，新加的 `khc-webssh` 公钥就**不能带 restrict**。这不只等于「Hub 失陷则 Peer 失陷」，而是 **Peer 的 `authorized_keys` 里多了一把无限制的完整 shell 公钥**，任何能读到 Hub 私钥的人都能直接 ssh 进 Peer。ADR-0020 按这个口径写，并明确：两把公钥用途与权限必须分列文档、不得合并；Hub 私钥 0600；S2 接入向导须提示「这把公钥能开完整 shell」 |
| 核心冻结（`agent/khc/`） | K1 下改动集中在新的 `terminal` 适配器和 `caddy_site` 的一条路由；Agent 动作经现有的 HMAC 通道 |
| Workers 额度 | 每次开会话约 2 个 Worker 请求，不使用 DO |

## 5. 范围与不做

- 做：Hub 终端、Peer 终端（经 Hub）、脚本任务、`KHC_RESULT` 解析、脚本库、按需安装 ttyd。
- 不做：IP 直连节点的终端、经 Worker 中转、断线续接（用 tmux 代替）、SFTP、多人同时操作一个会话、面板保存私钥。

## 7. 风险

- ttyd 最新 release 是 2024-03-30 的 1.7.7（已核 GitHub Releases API）。功能稳定但发版不频繁；S0 要核对发行版源里的版本有没有已知漏洞。
- 随机路径口令（K1）在有效期内若泄露，可直接拿到 root shell，且 `-O` 不保护页面 GET。缓解措施见 §4.1 的四条硬要求；「只能用一次 + 60 秒 + 校验 Origin + HTTPS」只是其中一部分。
- `systemd-run` 起的是真正的 root shell，权限与主人自己 SSH 登录相同。
- **动态上游让路径参与 socket 路径拼接**，id 校验不严会导致路径穿越或 Caddyfile 注入；S1 必测（§3.1）。
- 测试期不强制 TOTP 且 WebSSH 一旦打开即为 root shell，**默认关闭开关是上线前的唯一兜底**，不得因为「测试方便」而默认开启。
