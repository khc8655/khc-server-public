# UI 变更单 #008：主机运维（Hub + Peer）

- 状态：已实现（2026-10-26，staging 真机；截图 docs/ui/shots/hostops-*.png）
- **2026-10-29（#50）**：进程抽屉改为只读，撤销本单 §3 的「结束」行内动作与确认框，详见 #015。
- 依据：`docs/host-ops.md`
- 路由：不新增路由与侧栏项；入口挂在已有页面上

## 1. 作用域与流程

- 节点层操作；对象是“主机”（Hub 本机或某个 Peer），不新增业务对象。
- **按需**：任何数据都要用户点按钮才获取，不自动连接、不轮询。
- 写操作（结束进程、改防火墙、增删公钥）一律经确认，并进入活动/审计。

## 2. 入口与布局

| 位置 | 内容 |
|---|---|
| 节点概况「VM 运维」卡片（#007） | 卡片底部新增三个动作：进程、 防火墙、SSH 公钥 → 打开对应抽屉，`target=self` |
| WireGuard 页 → Peer 行 → 抽屉 | 新增「运维」标签：未接入 / 已接入两种形态 |

「运维」标签（已接入）结构：

1. 顶栏：主机名、脚本版本、「获取状态」按钮、「数据来自 N 分钟前」；
2. 状态区：复用 #007 卡片布局（`status` 输出与 `/state.ops` 同构）；
3. 三个分区按钮：进程、防火墙、SSH 公钥 → 打开二级抽屉（与 Hub 共用同一组件，`target=<peerId>`）。

## 3. 二级抽屉

| 抽屉 | 模板 | 内容 | 动作 |
|---|---|---|---|
| 进程 | T2 列表 | Table：PID、用户、CPU、内存、启动时间、命令（Truncate 中间截断）；排序 CPU/内存 | 行动作「结束」→ ConfirmAction（显示 PID+命令）；勾选“强制”才发 `force` |
| 防火墙 | T4 配置 | 本系统规则表（允许/拒绝、协议、端口、来源、备注）+ 其他规则只读折叠区；锁定行（SSH/WG/Hub/8880）显示锁标识不可删 | 编辑 → SaveBar 显示 diff → 应用 → 倒计时 60 秒「等待确认连接」→ 成功/已自动回滚 |
| SSH 公钥 | T2 列表 | 指纹、类型、备注、来源（本系统管理/手工） | 添加（只接受公钥文本，校验格式）；移除（仅本系统管理，Hub 运维公钥不可移除） |

## 4. 未接入形态（首次接入向导，T5）

1. 说明：Peer 上不会安装常驻程序，只放一个脚本和一把受限公钥；
2. CodeBlock + CopyButton：一键接入命令；
3. 「检查连接」→ 显示主机密钥指纹 → 「确认指纹」；
4. 自动获取状态，成功后切到已接入形态。
同一位置提供「卸载命令」。

## 5. 组件

Tabs、Card、KeyValue、Stat、Table、Truncate、Tag、Drawer、ConfirmAction、SaveBar、CodeBlock、CopyButton、Steps、Badge、Banner/InlineError、EmptyState；**不新增组件、不写自定义样式**。

## 6. 文案

- 时间：「数据来自 3 分钟前」；从未获取：「尚未获取」。
- 防火墙提示：「这里的“允许”不能放行被系统其他防火墙规则拦截的流量。」
- 非 root：「该主机没有管理员权限，仅可查看。」
- 错误码按 `docs/host-ops.md` §8 映射为中文提示，不展示原始英文错误码（详情区可展开原文）。

## 7. 状态覆盖

未接入 / 获取中 / 成功 / 失败（按错误码）/ 无权限只读 / 脚本需更新 / 防火墙等待确认 / 防火墙已自动回滚。
