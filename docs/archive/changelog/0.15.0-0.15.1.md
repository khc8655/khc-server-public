# Changelog Archive (`0.15.0` – `0.15.1`)

## [0.15.1] - 2026-11-16
### Added
- 主机运维「服务」列表对失败单元提供「清除失败状态」：只清 systemd 的失败标记，不启动服务、不改配置；确认框写清这一点，单元仍在失败循环时会提示「服务本身还没修好」（需 Agent 0.3.3，仅 Hub 本机可用）。
### Fixed
- 失败计数不再冻在打开页面那一刻：10 秒快照现在带上失败单元，状态带与概况页随之刷新，重启或清除失败状态成功后计数会自己归零，不需要重开页面（需 Agent 0.3.3）。
- 读不到失败单元时不再显示「0 个失败」，改为「未读取」：旧 Agent 下会退回读 `/state`，两者都不给时才说不知道。

## [0.15.0] - 2026-11-16
### Changed
- 节点栏不再显示地址：只留状态点与节点名，节点名在窄屏不再被截断；地址只在概况页标题下出现一次（灰色主机名，悬停出现复制）。
- 概况页「对外服务」改为逐行列名字（网页服务 / 远程访问 / Peer 各最多 5 行，超出给「全部 N 个 ›」），计数只留上方指标卡，不再上下各说一遍。
- 节点栏新增统一连接指示：三态「实时 · 直连 / 实时 · 经控制面 / 离线」，点开可看每类数据走哪条通道。去掉「实时状态」卡片上容易误读的「直连」标签（它只说明指标通道，主机运维一直经控制面）。
- 「需要处理」只放面板能处理的单元（khc-*、caddy、wg-quick@*、khc-app-*）；系统自带单元的失败改为在「主机与服务」卡片给一行灰色入口，不再长期挂在待办里。
- 「系统错误（近 24 小时）」改名「近 24 小时日志错误」，并注明是历史记录、修复后不会立即消失。
### Fixed
- 重启服务成功后状态带的失败计数会立即更新：过去只重拉服务列表，计数停在打开页面时的旧值，出现「列表已无失败单元、计数还显示 1」。真机还发现 Agent 的 `/state` 运维采集有 5 秒进程内缓存，仅失效查询仍会读到旧值，因此改为写成功后带 `?force=1` 重新拉取（需 Agent 0.3.2）。
- 面向用户的「异常」统一改为「失败」，并在 UI 规范里把「失败」列为合法状态词（此前只禁止「异常」却没给替代词）。
