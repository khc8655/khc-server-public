# Changelog Archive (`0.17.0` – `0.17.5`)

## [0.17.5] - 2026-11-17
### Fixed
- 主机运维「进程」列表不再出现空白行：采集窗口内退出的进程（多为 `ps` 命令自身）读不到名字和命令行，之前会作为一条空记录展示，现已在 Agent 侧丢弃（需 Agent 0.5.4）。

## [0.17.4] - 2026-11-17
### Fixed
- 修复每个复用连接上的请求固定多出约 40 毫秒的问题（HTTP 服务端未关闭 Nagle 算法，触发 TCP 延迟确认）。实测同一连接第 2 个及之后的请求从 41ms 降到 0.5ms，页面内连续操作明显更快。新建连接不受影响，所以之前单次测试一直没发现。
### Changed
- C2（只读运维改浏览器直连）经实测不做：Worker 与 Hub 同在新加坡，那一跳只有 3ms，远低于 150ms 门槛。规则本身（通道分类）已按 ADR-0020 落地。

## [0.17.3] - 2026-11-17
### Added
- 新增 ADR-0020「节点数据通道分类」：把「哪些数据可以由浏览器直连」写成成文规则（观测 / 只读运维 / 变更与机密三类），并明确公钥清单与日志永不直连。这条规则解决的是治理问题——新增功能时有明确依据，误标只读会被测试拦住。
### Changed
- host-ops 的 18 个动词都声明了通道类别，导出到共享契约包供面板与控制面读取；两份声明由测试做一致性校验，漂移即失败。

## [0.17.2] - 2026-11-16
### Fixed
- 「全部流量走 Hub」的客户端配置会钉住 Hub 地址的直连路由，避免默认路由把封装包投回隧道自己（此前选这个选项会让隧道当场失效）。
- Peer 安装脚本的重启流程补了一次接口清理兜底：路由被改过后 `wg-quick down` 可能失败并留下半配状态接口，导致下次启动撞 "File exists"。
### Changed
- 「全部流量走 Hub」暂时置灰不可选：真机验证发现经 Hub 出网不通，根因待查，恢复前请保持「仅内网流量走 Hub」。

## [0.17.1] - 2026-11-16
### Changed
- 防火墙段与 SSH 公钥面板的加载提速：原本「先取版本号、再取数据」要串两次，现在同时发。对 Peer 目标收益更明显（那一跳走 SSH，串行会把两段网络往返相加）。

## [0.17.0] - 2026-11-16
### Changed
- 主机运维整体提速：本机调用不再每次都启动一个 Python 进程重跑运维脚本，改为在 Agent 内直接执行。实测 `version` 从 129–190ms 降到 2ms，`svc.list` 从 132–191ms 降到 8ms，打开主机运维页明显更快（需 Agent 0.5.0）。
### Fixed
- 运维脚本的写操作在 Agent 沙箱内写错目录的问题：执行前显式对齐状态目录，写操作落到数据目录而不是只读的 `/etc`。
