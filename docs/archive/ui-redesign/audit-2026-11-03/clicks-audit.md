## 1. 阻断项

### B-1 创建 Peer（暂存）后自动弹出的导出抽屉报「peer 不存在」

- 页面：节点 › 内网穿透；元素：创建 Peer 后自动打开的「导出 Peer 配置」抽屉。
- 截图：`14-peer-created.png`、`18-peer-export.png`。
- 期望：创建 Peer 后直接给出客户端 .conf 与一键安装脚本（本次走查清单第 4 项）。
- 现状：点「保存」（暂存，不生效）后，抽屉自动切换为导出视图并显示「导出失败 / peer 不存在: audit-test-peer」，带「重试」按钮；从行菜单「导出配置」手动重试同样失败（2/2 复现，第二个 peer 同样）。关闭抽屉后列表中 Peer 实际已创建成功（待生效）。
- 根因（代码定位）：导出走 Agent 动作 `peer_install_script`（apps/web/src/apps/wireguard/page.tsx:525），Agent 只认识已下发配置；暂存 Peer 尚未「应用配置」，Agent 侧自然不存在。报错文案来自 agent/adapters/wireguard.py:1973。
- 是否规范偏差：是。错误提示不可操作——没有告诉用户「先应用配置再导出」，与 UI 规范「失败要指出原因与下一步」不符。属于流程编排缺陷而非崩溃：面板其余功能正常。
- 建议：暂存态导出应改由 D1 配置生成脚本，或在导出抽屉检测「待生效」状态时给出「先应用配置」引导；至少把 Agent 的 peer_not_found 转译为可理解文案。
