# 面板 WebSSH 与脚本任务（提案）

> 状态：草案 ｜ 最后核验：2026-11-15 ｜ 关联：`docs/plans/diagnostics-and-terminal-2026-11-13.md`、ADR-0007、`docs/security-boundaries.md`

> **执行者须知**：草案阶段不实施。§8 拍板、本提案合并后，才从批次 S0 开工。本提案取代 diagnostics-and-terminal 提案的批次 4（T-A）和 §8 的 R-4 到 R-7。

## 1. 背景与主人的决定

主人要的是：

1. **手动安装**：在面板里 SSH 进 Hub 或 Peer（VM），运行第三方一键脚本，回答交互菜单，看到最终输出。
2. **自动安装（以后）**：对自研应用，面板直接下发一键脚本，读回脚本生成的结果，不再需要外部 SSH 客户端。

2026-11-15 的讨论结论：

- 不用 Cloudflare Access 的浏览器 SSH：每台机器都要装 `cloudflared`，主人不接受。
- 不走 Agent 自建终端（原 T-A + R-7）：工作量大，只覆盖 HTTPS 入口节点，Peer 还要另装一个 Agent。
- **采用路线 A：Worker 用 `cloudflare:sockets` 直连节点 sshd**。主人的 VPS 本来就对公网开放 22 端口，不构成新的暴露面。一套 SSH 客户端同时覆盖交互终端和脚本任务（exec）。

## 2. 架构

```
浏览器 xterm.js ──WebSocket──▶ Worker ──▶ Durable Object（每会话一个）
                                              │ cloudflare:sockets
                                              ▼
                                         Hub sshd :22
                                              │ direct-tcpip（Hub 当跳板）
                                              ▼
                                         Peer sshd :22（WG 地址）
```

- SSH 握手、认证、加密都在 Durable Object 里完成。浏览器只收发终端字节，拿不到私钥。
- Peer 没有公网地址，经 Hub 的 `direct-tcpip` 通道跳到它的 WG 地址，等价于 `ssh -J hub peer`。
- 每个会话独占一个 Durable Object。浏览器断开后会话可保留一段时间，重新打开能接回（见 §4.4）。
- 脚本任务复用同一个客户端，走 `exec` 通道，不分配 pty。

## 3. 与现有规则的冲突（需主人逐条解除）

| 规则 | 出处 | 本提案的处理 |
|---|---|---|
| 不做 WebSocket、DO | `AGENTS.md` §1 | 只限 WebSSH 使用，其他功能仍不得使用。改 `AGENTS.md` §1 加上这条例外 |
| 面板不与节点保持长连接 | 2026-11-12 主人定案、ADR-0010 | 观测通道不变。终端会话是主人主动打开的，关闭或空闲超时后连接即断 |
| 不新增终端模拟器依赖 | `ui-guidelines.md` §9 | 只允许终端页使用 xterm.js，按路由懒加载，不进主包 |
| 不做 Web Shell、任意命令 | `docs/diagnostics.md` §7 | 诊断里仍然不做；WebSSH 是单独的功能页 |
| Hub 失陷也拿不到交互式 shell | ADR-0007 | 不改变 Agent 和 host-ops 的边界。新增的风险在面板一侧：**面板会话 = 已配置节点的 root**，写进新的 ADR-0020 |

## 4. 设计

### 4.1 SSH 客户端库（待拍板 W-1）

| 选项 | 许可证 | 现状 | 优点 | 缺点 |
|---|---|---|---|---|
| **L1 `@workeryard/undershell`** | MIT | 0.2.0，自述 Experimental；187 个单元测试，对 OpenSSH 7.4 到 10.3 跑过 947 个用例；协议约 3300 行，没做过独立安全审计 | 是库而不是应用；零依赖，只用 WebCrypto；原生支持 exec、pty、跳板机，强制校验主机密钥指纹 | 很新，API 在 1.0 前可能变；没有生产流量验证 |
| L2 参考 `cmliu/CF-Workers-WebSSH` 自己抽取 | Apache-2.0 | 应用形态，约 90 star | 结构和本方案一致（DO + xterm） | 是完整应用，要拆出来维护，等于自己背协议代码 |
| L3 npm `ssh2` 加 Node 兼容层 | MIT | 成熟，Node 生态主流 | 协议实现久经考验 | 依赖 Node 兼容层和 socket 桥接，Worker 包体积和兼容性要实测 |

推荐 **L1，锁定精确版本**，S0 里对测试节点的 OpenSSH 实测。如果 S0 失败，退到 L3。

### 4.2 凭据与主机密钥（待拍板 W-2）

- **登录密钥**：面板生成一对专用 ed25519 密钥（`khc-webssh`）。私钥经 `MASTER_ENC_KEY` 用 AES-GCM 加密存入 `settings`，只写不回读；面板只显示公钥，由主人加到 Hub 和 Peer 的 `authorized_keys`。不支持密码登录。
- 备选：主人上传自己的私钥。不推荐，因为它多半还用在别处，泄露面更大。
- **登录用户**：按节点配置，默认 `root`。
- **主机密钥**：首次连接时显示指纹，主人确认后存入 D1（TOFU）；之后指纹变化就拒绝连接，并提示主人重新确认。
- **Peer 账号**：现有 host-ops 的受限公钥（`command="sudo -n /usr/local/sbin/khc-host"`）保持不变，另外加 `khc-webssh` 公钥。Peer 的 sshd 要能在 WG 地址上接受连接。

### 4.3 鉴权与审计

- Worker 签发一次性会话票据，60 秒有效，绑定面板 Origin。
- TOTP 与 WebSSH 的关系见 W-6：测试期主人不启用 TOTP，所以 WebSSH 默认关闭，由设置里的开关打开。TOTP 未启用时，终端页顶部常驻警示「未启用两步验证：面板密码即节点 root」。专用公钥只加到测试节点上。
- D1 `audit` 记录节点、开始时间、结束时间、时长、结束原因，不记录终端内容。
- 是否记录输入（待拍板 W-3）。原决定是在节点本地落 0600 文件、保留 7 天，但那是 Agent 方案的做法，路线 A 下节点上没有我们的进程。可选：
  - A：不记录输入，只记会话元数据；
  - B：DO 里按行记录输入，密码提示后的那一行打码，加密存入 D1，7 天后清理（这会改变「D1 只存配置」的口径）。
  - 推荐 A。

### 4.4 会话（待拍板 W-4）

- 同一节点同时最多 1 个交互会话。
- 空闲 10 分钟（既无输入也无输出）自动断开，不设总时长上限，避免打断编译类脚本。
- 浏览器断开后，DO 保留 SSH 会话 10 分钟，并缓存最近 64 KB 输出；同一面板重新打开时自动接回。

### 4.5 脚本任务（批次 S3）

- 在面板里选节点，粘贴或选择脚本，以 `exec` 方式执行（非交互），实时显示输出，结束后显示退出码。
- **结果约定**：脚本最后输出一行 `KHC_RESULT {json}`，例如 `{"port":3245,"url":"http://127.0.0.1:3245"}`。面板解析这一行；如果带端口，直接接到「发布本机端口」。字段名含 `password`、`secret`、`token` 的值只显示一次，不落库。
- 脚本库（原 R-8）：全局设置里保存「名称 + 命令」，不存凭据。手动安装可以一键在终端里输入该命令，交互部分由主人完成。

## 5. 范围与不做

- 做：Hub 终端、Peer 终端（经 Hub 跳板）、脚本任务、`KHC_RESULT` 解析、脚本库。
- 不做：SFTP 与文件管理、端口转发、多人同时操作同一会话、经 Cloudflare Tunnel 连接 sshd、密码登录、终端输出存储、账号密码正则抓取。
- 不变：Agent、host-ops 动词和受限公钥、10 秒快照观测通道、T-C「发布本机端口」。

## 7. 前置条件

1. **TOTP**：测试期不开（主人 2026-11-15 决定，避免每次登录都要输入）。不再作为 S1 开工的前提；正式上线、把专用公钥加到生产节点之前必须开启。
2. 核实 `workers_dev` 入口是否用同一套登录和 TOTP 校验。`AGENTS.md` §3 第 5 条要求它保持开启，所以只核实，不关闭。
3. 主人确认 Hub 的 sshd 已只允许密钥登录（`PasswordAuthentication no`），并已有 fail2ban 或同类防护。这不由面板管理，只在接入向导里提示。
