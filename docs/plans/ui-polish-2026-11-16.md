## 0. 来源

主人 2026-11-16 在 oracle-x86-2 上看了概况页和主机运维页（截图存在主人的对话里，没有入库），提了 6 个问题。下面逐条给出代码核查的结论和改法。

## 1. 节点栏的域名框太难看

**现状**：`ui/shell.tsx` 的 `HubBar` 把 `endpoint` 画成一个带边框、灰底、等宽字体的框（`.ui-hubbar-node-endpoint`）。这个框还挤压节点名，截图里节点名被截成了「oracle-x86-」。同一个地址在概况页又出现了两次：「实时状态」卡片里一次，页脚一次。

| 选项 | 做法 |
|---|---|
| A（推荐） | 节点栏里去掉地址，只保留状态点和节点名，节点名不再被截断。地址只在概况页标题下出现一次，用灰色纯文本显示主机名（去掉 `https://`），悬停时出现复制按钮。「实时状态」卡片和页脚里的地址都删掉 |
| B | 节点栏保留地址，但改成纯文本（无边框、无底色、非等宽），只显示主机名，宽度不够时先隐藏 |

## 2. 概况页重复计数；在线状态的颜色规范

**现状**：上面的指标卡已经给了「站点 1 / 反代 1」「Peer 在线 1/1」，下面的「对外服务」卡片又写了一遍「1 个站点 · 本机 1」「Peer 1/1 在线」，两处信息完全一样。

**改法（只有一种，没有可选项）**：上面负责计数，下面负责列名字。

- 「网页服务」：每行一个站点，显示「状态点 + 域名 + 后端」，例如 `● app.example.com → 127.0.0.1:3245`。最多 5 行，超过时加一行「全部 N 个 ›」。
- 「远程访问」：每行一条转发规则，显示「名称 + 对外端口 → 目标」。未安装时保持灰色「未安装」一行，不展开。
- 「Peer」：每行一个 Peer，显示「状态点 + 名称 + 最近握手时间」，同样最多 5 行。
- 整行可点，悬停时出现灰色「›」。沿用 2026-11-12 的定案，不使用蓝色链接。

**颜色规范**：已有统一规定，见 `ui-guidelines.md` §8.1：绿色表示在线 / 已生效，琥珀色表示待生效 / 临期，红色表示失败 / 离线，灰色表示停用 / 未安装；导航和列表用 7px 圆点，状态列用 Badge。页面实际违反了两处：

- 「服务异常」「1 个异常」用了禁用词（§「状态词只用」那条规定）。统一改为「失败」。
- 列表的 `StatusDot` 和状态列的 Badge 混用，要按上面的规范统一。

执行 PR 时用 grep 把所有违规点列出来，一并修掉。

## 3. 失败服务的提示不要占「需要处理」的位置

**现状**：概况页的 `TodoChips` 会把 `systemctl --failed` 里的每一个单元都放进「需要处理」，包括 `unattended-upgrades.service` 这类和面板无关的系统单元。面板管不了它们，所以提示会一直挂在那里。

| 选项 | 做法 |
|---|---|
| A（推荐） | 「需要处理」只放面板管理的单元（`khc-*`、`caddy`、`wg-quick@*`、`khc-app-*`）。其他失败单元只在「主机与服务」卡片里显示一行灰色的「系统服务 1 个失败 ›」，点进去到主机运维页处理 |
| B | 保持全部放进「需要处理」，但每条加「忽略」按钮。忽略按节点记住，写进 settings，直到该单元恢复后又一次失败才重新出现 |
| C | 概况页不再提系统单元，只在主机运维页显示 |

不管选哪个，主机运维的「服务」列表里，失败单元都增加一个「清除失败状态」操作（`systemctl reset-failed <unit>`）。这是一个新的写动词，需要白名单、审计和二次确认，见 P-3b。

## 4. 主机运维是不是浏览器直连？直连慢、不能直连时怎么显示？

**核查结论（以代码和现行文档为准）**：主机运维**从来不是浏览器直连**。

| 数据 | 通道 | 依据 |
|---|---|---|
| CPU / 内存 / 磁盘 / 负载（10 秒刷新） | 节点有可信域名（https + 域名，或 Tunnel）时，浏览器直连 `/_live/snapshot`；没有时由 Worker 转发 | `docs/live-observation.md` §1 |
| 服务、进程、防火墙、SSH 公钥、定时任务（读和写） | **一律经 Worker**：`POST /api/v1/nodes/:id/apps/host-ops/call`，再由 HMAC 调到 Agent | `apps/web/src/data/hostOps.ts` |
| 服务清单、失败单元、适配器状态 | 打开工作区时由 Worker 调一次 `/state`，之后不再刷新 | `docs/live-observation.md` §1 |

所以，「实时状态」卡片上的「直连」两个字只说明指标走直连，不代表主机运维也直连，这个标签造成了误解。没有域名的节点，主机运维照样可以用。

**慢在哪里：还不知道（待 S0 验证）**。可能的原因有三个：Worker 到 Agent 的往返、Agent 执行 `systemctl` / `journalctl` 本身的耗时、Peer 经 SSH 跳转的耗时。在没测量之前，不应该改通道。

| 选项 | 做法 |
|---|---|
| A（推荐） | 不改通道。S0 先给每类调用分段计时，按结果针对性优化，例如列表加缓存、优化慢动词。UI 上把「直连」改成节点栏里统一的一个连接指示：「实时 · 直连 / 实时 · 经控制面 / 离线」，点开可以看到每类数据走哪条通道。主机运维页不因为没有域名而关闭 |
| B | 只读动词也改走直连（`/_live/ops?ticket=`），写操作仍经 Worker 并审计。需要新增票据作用域、Agent 端点和 CORS，并且要动冻结核心 `agent/khc/live.py`。等 S0 证明瓶颈确实在 Worker 往返后再考虑 |

## 5. 重启了出错的进程，但错误计数没变

**核查结论**：这里有两个计数，各有各的原因。

1. **状态带「服务 1 个失败」**：这个数来自打开页面时那一次 `/state`（`HubOpsPage.tsx` 第 103 行）。10 秒快照不包含失败单元，「刷新」按钮只重新拉服务列表（`svc.list`），所以重启成功后列表变了，计数却停在旧值。截图里列表已经没有失败单元，状态带却还显示 1，正好对上这个原因。这是缺陷。
2. **「系统错误（近 24 小时）」22 条**：这是 `journalctl` 的历史记录，修好之后也会在 24 小时内一直存在。这是设计上的行为，但页面没有说清楚。

**改法**：

- 失败单元列表并入 10 秒快照（Agent 每 10 秒多调一次 `systemctl list-units --state=failed`，待 S0 验证这次调用的耗时）。状态带、概况页和「需要处理」都改为读快照。
- 重启、清除失败状态等写操作成功后，立即重新拉一次快照和服务列表。
- 「系统错误」改名为「近 24 小时日志错误（历史记录，修复后不会立即消失）」，按单元分组计数，并在组标题上显示该单元的当前状态，例如「khc-r3-driver · 当前：运行中」。

## 6. 添加 Peer 时缺少网络配置

**现状**：

- 服务端 PostUp 是 `iptables -A FORWARD -i wg0 -j ACCEPT` 和 `-o wg0 -j ACCEPT`，见 `wireguard.py` 的 `default_post_up`。这意味着**所有 Peer 之间默认互通**，而且只要客户端自己把 `AllowedIPs` 改成 `0.0.0.0/0`，就能经 Hub 出网（Hub 已经对外网卡做了 MASQUERADE）。
- 客户端配置的 `AllowedIPs` 默认是整个 WireGuard 网段。`client_config` 接口支持传入 `allowed_ips`，但面板没有提供这个入口。

**目标**：

- 新 Peer 默认**只能和 Hub 通**。
- 可以选择与哪些 Peer 互通：「全部 Peer」或「指定 Peer」，指定时互通是双向的。
- 可以选择「全部流量走 Hub」，选中时**必须弹出风险确认框**。

**改法**：

- Peer 抽屉新增「网络」区，包含两项：
  - **可达范围**：仅 Hub（默认）/ Hub + 指定 Peer / Hub + 所有 Peer。
  - **出网方式**：仅内网流量走 Hub（默认）/ 全部流量走 Hub。
- **服务端强制执行，不只靠客户端配置**：由适配器渲染 `wg0 → wg0` 的 FORWARD 规则，先按 Peer 对放行，再默认 DROP；`wg0 → 外网` 只对选了「全部流量走 Hub」的 Peer 放行。客户端配置的 `AllowedIPs` 跟着生成：仅 Hub 时是 Hub 的 /32，与其他 Peer 互通时加上对方的 /32 或整个网段，全部流量走 Hub 时是 `0.0.0.0/0`。
- 选「全部流量走 Hub」时弹出 L2 确认框（需要勾选「我已了解」），说明以下风险：
  - VM 原有的公网入站，例如它自己公网 IP 上的 SSH，可能因为回程路由改走隧道而断开（待 S0 验证）；
  - Hub 一旦断开，这台 VM 就完全断网；
  - 这台 VM 的全部流量都计入 Hub 的带宽和流量费用；
  - DNS 需要另外配置，否则仍走本地解析。
- **存量 Peer**：迁移时一律标为「Hub + 所有 Peer」，保持现在的连通性不变。新的默认值只作用于新增的 Peer。
