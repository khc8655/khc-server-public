## 1. 背景

主人 2026-11-20 对概览页提出的要求（原话收敛）：

1. 概览是「总览」：**不放主机指标**（CPU、内存、磁盘、系统、运行时长），这些进 VM 才看。只放首页现有接口（`GET /nodes`、`GET /certificates`、`POST /nodes/probe`）里已有的内容。
2. 卡片**一行两张**，不要堆多列小字，「没用的东西」（URL 原样、「运行中」、最后在线）不占重要位置。
3. 核心指标：**应用在线 / 总数、Peer 在线 / 总数**。
4. VM 到期时间：只记一个固定日期，**不做自动顺延**。
5. 三种接入方式（域名、Tunnel、IP 直连）都要有合理显示；IP 直连的节点也可以有应用证书。
6. **功能开启才显示，界面上不许出现「0 个」。**
7. **应用 = 通过 Caddy 反代出来的服务**（例如 hermes）。没经过 Caddy 的自装软件（例如 sing-box）放进 VM 详情维护，概览不显示。
8. 应用在线：Caddy 会报状态，**端口 down 就算异常**。
9. 「站点」这个叫法容易误解，VM 内改叫「应用」。
10. 概览与点进去的 VM 工作区口径必须统一。

## 2. 统一规则（全站）

| 规则 | 内容 |
|---|---|
| R1 术语 | **应用**：已启用的 Caddy 反代（`kind=proxy`），一条算一个。**组件**：Caddy、WireGuard、转发、node-exporter 等内置项。**服务**：没经过 Caddy 的自装软件（目录应用未发布者），只在 VM 内出现。静态站点与跳转不算应用。 |
| R2 开启才显示 | 组件未装或产物为 0 时，对应统计格、摘要、分组、KPI 一律不出现。界面不出现「0」「0 / 0」「—」「暂无」。 |
| R3 全部离线 | 已开启但全部离线时写「N 个离线」（红），不写「0 / N」。 |
| R4 异常即待办 | 应用异常、Peer 离线、证书 ≤14 天、VM ≤14 天到期，统一进入「需要处理」，点击直达。为 0 时整格隐藏。 |
| R5 接入方式 | 连接行 = 接入方式 chip + 地址 + 接入安全性。域名：「HTTPS · 接入证书剩 N 天」；Tunnel：「由 Cloudflare 边缘托管」；IP 直连：灰色「HTTP 明文 · 无接入证书」，是主动选择，不算异常。 |
| R6 证书 | 应用证书与接入证书分开。统计格「证书」= 证书库中 `sourceNodeId` 为本节点或覆盖本节点域名的证书数，附最近到期天数。只统计证书库，Caddy 自动签发的不计（文案注明）。 |

### 2.1 应用在线判定（不改 Agent）

`caddy_site._probe_url` 经 Caddy 对每个启用站点做 HEAD/GET：`<400` 记 `ok`，任何 HTTP 错误码记 `warn`，连接失败记 `down`，自签证书记 `warn`。**上游端口 down 时 Caddy 自己仍在，会回 502，被记成 `warn`**，因此面板必须按状态码自行判定：

| siteHealth | 面板判定 |
|---|---|
| `ok`；`warn` 且 status 为 4xx；`warn` 且为自签证书 | 在线 |
| `warn` 且 status 为 502 / 503 / 504；`down` | 异常（进「需要处理」） |
| `unknown`（未探测、超预算） | 未知，不计入在线也不计入异常 |

判定函数做成纯函数并单测，概览与 VM 内共用同一份。

## 3. 概览页

- **KPI 四格**：VM 在线、应用在线、Peer 在线、需要处理。按 R2：没有任何应用或 Peer 的格子不显示；需要处理为 0 隐藏。
- **VM 卡片（一行两张）**，三层：
  1. 名称 + 到期 chip（配置了才显示，≤14 天标黄）+ 在线点；

  3. 统计格：应用在线、Peer 在线、转发、证书，按 R2 只显示有的，靠左排列不留空位。

## 4. VM 工作区

| 位置 | 现状 | 改法 |
|---|---|---|
| 侧栏「站点」 | 名称易误解 | 改名「应用」。页内分段：应用（反代）／静态与跳转（存在时才显示）／证书（有关联证书才显示）。路由 `/hubs/:id/sites` 不变 |
| 侧栏「内网穿透」 | 只看 `summary.peers` 或 `mode=wg`；转发卡也挂在这页 | 有 Peer **或**有转发规则即显示（待核实只有转发时入口是否已消失） |
| 侧栏「服务」 | 列服务单元 | 增加「服务」分组：目录装但未经 Caddy 的软件（sing-box 等）在此维护 |
| 概况 · 指标卡 | 站点为 0 也显示；未装 WG 时 Peer 显示「—」 | 与概览卡同一组统计格（应用在线、Peer 在线、转发、证书），按 R2。主机指标（负载、内存、磁盘、系统、运行时长）单列一张「主机」卡，只在 VM 内 |
| 概况 · 对外服务卡 | 未装 WG 也出现「Peer 未安装」（`peerRows` 未装时仍返回组）；空组显示「暂无」 | 未装或为空的组不显示；全空则整卡隐藏 |
| 概况 · 页头 | 连接与证书只在页脚一行小字 | 页头放连接行（R5）与到期 chip，页脚删去重复 |
| 概况 · 需要处理 | 失败单元、临期证书、离线 Peer | 加「应用异常」「VM 即将到期」（R4） |
| 文案 | 「应用」既指内置项又指目录应用；「扩展应用」 | 内置项改称「组件」，「扩展应用」改「服务」。组件详情路由 `/apps/:app` 不变，避免书签失效 |

## 5. 数据来源与方案对比

概览只有一次 `POST /nodes/probe`，Worker 对每个节点取 Agent `GET /state`，当前 `probeApps()` 只投影适配器名与 installed/running。`/state` 里其实已有 `wireguard.status.peers[].online` 与 `caddy-site.status.siteHealth[]`。

| 选项 | 做法 | 优点 | 缺点 |
|---|---|---|---|
| **A（推荐）** | Worker 在 `apps/api/src/lib/` 新增投影模块（与 `node-summary.ts` 同层），按适配器名提取 `peers{online,total}`、`apps{online,total,issues[]}`（issues 只带站点名与状态码），probe 响应新增可选字段 | 不改 Agent，旧 Agent 立即生效；不增请求；应用知识集中在 lib，`routes/nodes.ts` 仍不识别应用名 | Worker 要认识两个适配器的 status 结构（加 schema 与单测兜底） |
| B | Agent 每个适配器在 status 报通用 `gauge{online,total,issues[]}`，Worker 透传 | 通用，加组件无需改 Worker | 需 Agent 0.6.4，旧 Agent 退化为不显示；动适配器约定 |

推荐 A。VM 工作区本来就取完整 `/state`，直接复用同一判定函数，无需新接口。

到期时间需 `nodes.expires_at`（迁移 0014）。CI 目前硬编码 0013，依赖 PR #90 迁移常态化先拍板落地。
