## 2. 现状取证

### 2.1 产品定位（主人 2026-11-12 口述，以此为准）

- **WireGuard**：用来连接没有公网地址的 VM，再把 VM 上装的应用发布出去。
- **端口转发**：用来把这类 VM 的 SSH、远程桌面转发出来。
- **发布**：程序**手动安装**在节点或 VM 上（例：本机监听 `127.0.0.1:3245`），再由 Caddy 发布为域名。
- **必装组件只有 Caddy**。WireGuard、端口转发、扩展应用、目录应用都按需安装和启用。

## 4. 站点表「后端」列（第 3 批，B4-lite）

在现有 `/hubs/:id/sites` 站点表新增一列「后端」，作为「对外服务」页的推导先导。**不新增路由、不抽抽屉、不改请求数、不改写入链路。**

| 情况 | 展示 |
|---|---|
| 本机 | `本机 127.0.0.1:3245` |
| 内网 VM | `内网 VM <Peer 名> 10.x.x.x:3000` + 第二行 Peer 在线状态 |
| 内网未登记 | `内网 10.x.x.x:3000` + 中性提示“没有找到对应的 Peer” |
| 外部 | `外部 <host>:<port>` |
| 套接字 | `本机套接字` |
| 多上游 | 显示第一个后端，后写 `+N`（`pathRoutes` 不展开） |

推导规则（新文件 `apps/web/src/data/services.ts`，纯函数、不发请求）：

1. 剥 `http://` / `https://` 前缀；`unix//` → 本机套接字。
2. `localhost`、`127.0.0.0/8`、`::1` → 本机。
3. 命中已启用 Peer 的 `allowedIps`（`/32` 或网段）→ 内网 VM，带 Peer 名与在线状态。
4. 落在 `interface.address` 网段但无对应 Peer → 内网（未登记）。
5. 其他 → 外部；WireGuard 未安装时 10.x 上游一律归「外部」，不报错。

`services.ts` 是后端识别的唯一实现；第 4 批与站点页都复用它，不得在组件内另写 IP/网段判断。

## 5. `/hubs/:id/services`「对外服务」页（第 4 批）

### 5.1 定位

- 页面类型 **B（列表对象）**；只读聚合 + 复用既有抽屉；不引入新数据模型。
- 回答四个问题：发布了什么 / 后端是谁 / 通不通 / 有没有待生效。
- 写操作全部复用站点页与内网穿透页的现有抽屉与已注册动作（apply、删除等按动作注册表 L2/L3 确认），**不新增第二种详情或操作入口**。

### 5.2 信息结构：两张表

**表 A · 网页服务**（来源：`caddy-site` 中 `kind=proxy` 的站点）

| 列 | 内容 | 来源 |
|---|---|---|
| 服务 / 对外地址 | 第一行站点名；第二行 `域名:端口`（443 不写端口，等宽灰字） | 站点 `name`、`domains[0]`、`listenPort` |
| 后端 | `本机 127.0.0.1:3245` 或 `内网 VM <Peer> 10.x.x.x:3000`；VM 行第二行写 `Peer 在线` / `Peer 离线 N 天`（第 3 批 `services.ts`） | `upstreams[0]` + WireGuard 配置与 `/state` |
| 状态 | 圆点 + 文字：`正常 38ms` / `后端不可达` / `不可达` / `未生效` / `未读取` | `/state` `siteHealth` + 待生效判定 |
| 证书 / 访问（low） | `证书自动 · 公开` / `证书库 <名称>` / `证书关闭`；有 Basic Auth 时追加 `· Basic Auth` | 站点 `tls`、`basicauth` |
| 操作 | 行点击开站点抽屉；行尾 `⋯` 放非详情动作（打开、复制地址、删除）；未生效时「生效」在状态列右侧 | 既有站点抽屉与动作注册表 |

**表 B · 远程访问**（来源：`port-forward` 规则）

| 列 | 内容 | 来源 |
|---|---|---|
| 名称 / 连接地址 | 第一行 `note` 非空取 note，否则 `name`；第二行 `节点主机名:listenPort`（等宽灰字） | 转发规则 + 节点接入地址 |
| 目标 | `内网 VM <Peer> 10.x.x.x:22` + Peer 在线状态 | `targetHost` + WireGuard |
| 状态 | `可连接` / `目标不可达` / `转发未运行` / `未生效` / `未读取` | `/state` 转发 `active`/`error` + 待生效 |
| 协议（low） | `TCP` / `UDP` | `protocol` |
| 操作 | 行点击开转发抽屉；行尾 `⋯` 提供「复制连接命令/地址」 | 既有转发抽屉 + 前端生成 |

- 复制规则：`targetPort === 22` → `ssh -p <listenPort> <host>`；`3389` → `<host>:<listenPort>`；其余 → `<host>:<listenPort>`。不猜用户名。
- 底部一行灰色文字：`另有 N 个跳转/静态站点，见「站点」`；无则整行不渲染。
- 多上游显示第一个 + `+N`；`pathRoutes` 写 `+N 条路径规则`。

### 5.3 状态与待生效（取第一条命中）

| 条件 | 网页服务 | 远程访问 | 颜色 |
|---|---|---|---|
| `appliedRev !== rev`（D1 有未生效变更） | 未生效 | 未生效 | 琥珀 |
| `/state` 未读取（节点离线） | 未读取 | 未读取 | 灰 |
| 后端是 VM 且 Peer 离线 | 后端不可达 | 目标不可达 | 红 |
| `siteHealth.state === 'down'` / 转发 `active !== true` | 不可达 | 转发未运行 | 红 |
| 其余 | 正常 `Nms` | 可连接 | 绿点（只有圆点绿） |

- 待生效是**行级状态**，不弹横幅。**未生效时在状态列右侧直接给「生效」按钮**（复用既有 apply 动作，按 L2 确认），行内按钮仍 ≤2（「生效」+ `⋯`）。理由：发布会话里“已发布但未生效”最容易被忽略，收进菜单等于让用户继续猜。
- 同一 Peer 离线影响的多行，各自标红并在状态列写原因；概况页合并成一条待办（第 5 批）。

### 5.4 空态

| 情况 | 表现 |
|---|---|
| 表 A 为空 | 整表不渲染，只保留页头「新增站点」入口 |
| 表 B 为空 | 整表不渲染，只保留页头「新增转发」入口 |
| 两张都为空 | EmptyState「还没有对外服务」+ 主按钮「新增站点」+ 次按钮「新增转发」 |
| 节点离线 | 两张表仍渲染（D1 期望配置），状态列统一「未读取」，页头一条中性说明 |

### 5.5 路由、导航与入口

- 路由：`/hubs/:hubId/services`，页面标题「对外服务」。
- 侧栏顺序：概况 / **对外服务** / 站点 / 内网穿透（条件显示）/ 主机运维 / 节点设置。
- 页头：主操作「新增站点」= 打开**现有站点抽屉**；次操作「新增转发」= 打开**现有转发抽屉**。沿用术语表既有说法，不引入第三套叫法、不新写表单。
- 抽屉可直接从既有页面抽出复用；抽取时同步回归站点页与内网穿透页。

### 5.6 390 宽度方案

- 沿用 `ui-guidelines` §8.13：≤639 表格整体转为列表行，不做横向滚动（验收 `documentElement.scrollWidth === 390`）。
- 每行三段：① 名称 + 状态点；② 对外地址（等宽）；③ 后端（VM 行带 Peer 状态）。`⋯` 固定在行尾，触控目标 ≥32px。
- `证书 / 访问`、`协议` 为 low 优先列，<1024 隐藏；≤639 并入第 ② 段的尾部灰字，不单独占行。
- 名称、状态、行操作永不隐藏；长文本单行截断。

### 5.7 数据与请求预算

- 数据全部来自既有查询缓存：`caddy-site` 配置、`port-forward` 配置、`wireguard` 配置、`/state`（站点健康、转发运行态、Peer 在线）。
- **零新增请求、不新增轮询、不新增 D1 表**；任何 apply 成功后沿用现有失效机制刷新。
- 打开本页与打开站点页的请求数一致（同一工作区缓存）。

### 5.8 验收

- `services.test.ts` 覆盖全部识别与状态分支（含 IPv6、带 scheme 上游、多上游、Peer 停用、WireGuard 未安装）。
- 页面 smoke：两张表、空态、离线、待生效四种情况。
- staging：发布一个本机程序与一个 VM 程序，停掉 VM 的 WireGuard，确认「后端」与状态正确；390 实测无横向滚动。

## 9. 明确不做及原因
