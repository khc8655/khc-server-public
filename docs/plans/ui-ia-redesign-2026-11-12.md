## 2. 现状取证

### 2.1 产品定位（主人 2026-11-12 口述，以此为准）

- **WireGuard**：用来连接没有公网地址的 VM，再把 VM 上装的应用发布出去。
- **端口转发**：用来把这类 VM 的 SSH、远程桌面转发出来。
- **发布**：程序**手动安装**在节点或 VM 上（例：本机监听 `127.0.0.1:3245`），再由 Caddy 发布为域名。
- **必装组件只有 Caddy**。WireGuard、端口转发、扩展应用、目录应用都按需安装和启用。

### 2.3 当前体验问题

1. 站点页只能看到上游 IP，看不出是“本机程序”还是“某台内网 VM”，VM 掉线时也看不出原因是 Peer 离线。

3. 界面装饰性元素多（彩色胶囊、阴影、蓝色箭头链接、解释性副标题），信息密度被稀释。

## 4. 站点表「后端」列（B4-lite）

### 4.1 目的与范围

在现有 `/hubs/:id/sites` 站点表新增一列「后端」，回答“这个站点后面是谁、通不通”。**不新增路由、不抽抽屉、不改请求数、不改写入链路。**

### 4.2 列内容

| 情况 | 展示 |
|---|---|
| 本机 | `本机 127.0.0.1:3245` |
| 内网 VM | `内网 VM <Peer 名> 10.x.x.x:3000` + 第二行 Peer 在线状态（`Peer 在线` / `Peer 离线 N 天`） |
| 内网未登记 | `内网 10.x.x.x:3000`，附中性提示“没有找到对应的 Peer” |
| 外部 | `外部 <host>:<port>` |
| 套接字 | `本机套接字` |
| 多上游 | 显示第一个后端，后写 `+N`（`pathRoutes` 不展开） |

状态与颜色沿用站点表现有状态，不新增状态语义：未生效（琥珀）/ 未读取（灰）/ Peer 离线或站点不可达（红）/ 正常（绿点）。

### 4.3 推导规则（前端纯函数）

新文件 `apps/web/src/data/services.ts`，导出 `classifyBackend(hostPort, ctx)`，**不发请求**，输入全部来自已有查询缓存：

- `caddy-site` 配置（D1）与 `/state` 中 `caddy-site` 的 `siteHealth`；
- `wireguard` 配置（D1，`interface.address`、`peers[].allowedIps`、`peers[].name`）与 `/state` 中的 Peer 运行态（`online`）。

识别顺序：

1. 剥掉 `http://` / `https://` 前缀；`unix//` 开头 → `本机套接字`。
2. 主机是 `localhost`、`127.0.0.0/8`、`::1` → **本机**。
3. 主机命中某个已启用 Peer 的 `allowedIps`（`/32` 或落在其网段内）→ **内网 VM**，带 Peer 名与在线状态。
4. 主机落在 `interface.address` 网段内但没有对应 Peer → **内网（未登记）**。
5. 其他 IP 或域名 → **外部**；WireGuard 未安装时 10.x 上游一律归「外部」，不报错。

单测覆盖：每条识别规则、IPv6、带 scheme 上游、多上游、Peer 停用、WireGuard 未安装。

### 4.4 单一来源

`services.ts` 是「后端识别」的唯一实现；站点页只做展示，不得在组件内另写 IP/网段判断。后续若新增「对外服务」页，也复用它，不另起一套规则。

## 8. 明确不做及原因

| 不做 | 原因 |
|---|---|
| 新增 `/hubs/:id/services`「对外服务」页 | 收益集中在“看清后端”，站点表加一列即可覆盖；新增页面会扩大路由/侧栏/空态/390 的改动面，待 B3 验证后再评估 |
| 任务进度随快照下发（原 ADR-0018） | 需改 `agent/khc/` 与契约，属核心冻结；且要放宽 60 次轮询上限（转发模式约 180 次请求）。主人拍板维持 10 分钟 / 60 次，任务进度继续按现有手动查看 |
| 恢复 SSE / 长连接 / D1 任务表 | 与 ADR-0010 相反，或违反“面板不与 hub 保持长连接”的定案 |
| 托管安装 | 现有阻碍是 `generic-service` 单元/目录/recipe 模型不支持多实例，需单独提案 |
| 发布抽屉 / 远程访问抽屉增强 | 依赖不存在的「对外服务」页；本轮不动写入链路 |
| 修改 `packages/contracts/`、`migrations/`、`agent/khc/` | 本轮所有改动均为前端/文档；核心冻结区零改动 |

## 9. 风险

| 风险 | 缓解 |
|---|---|
| 后端识别误判（例如 VM 地址和 Peer `allowedIps` 不是 `/32`） | 网段匹配作为第二规则；无法确定时归为“内网未登记/外部”，不报错；单测覆盖 |
| 视觉改动影响面大 | B1 独立 PR，只改令牌和基础组件，gallery 页一次走查 |
| 站点表新增列在 390 宽度拥挤 | 低优先级列在窄屏隐藏（沿用现有 `low priority` 机制），后端信息保留在行详情中 |
