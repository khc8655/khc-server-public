# 域名与证书：统一信息架构与双入口（提案）

> 状态：草案 ｜ 最后核验：2026-11-21 ｜ 关联：`docs/cf-dns.md`、`apps/web/src/apps/node-settings/AccessForm.tsx`、`apps/api/src/routes/cfDns.ts`

> **执行者须知**：以面板（Web + Worker）为主，P4 才可能触及 Agent 站点编排。**IP 直连 / 域名 HTTPS / CF Tunnel 三种接入方式全部保留**，任何批次都不得删减或改变其语义。一个批次一个 PR。

## 1. 背景（主人 2026-11-21 的要求）

统一 VM 面板必须有完整的「账户 → 域名 → 解析」层级（参考截图：添加 DNS 账户、添加域名、添加 ACME 账户）。核心争点是：**添加新 VM 时必然要做解析，这个动作放统一配置里、放添加 VM 流程里，还是两处都有**；同时要考虑后续在哪看、在哪管理。最终目标：填域名 + 端口，装完即可用 HTTPS 访问。

现状有四个断点：

| # | 断点 | 证据 |
|---|---|---|
| 1 | 添加节点的「域名模式」**只能选已有记录**，无法直接输入自己的域名；非 Cloudflare 用户走不通 | `hubsCfDns.smoke.test.tsx`「域名模式：只选已有记录，不创建 DNS」 |
| 2 | `--with-caddy` **只安装 caddy 包**，不创建站点；`--tls-cn` **只在自签分支下发**，生产不再下发 | `agent/install.sh` L64/L70、`apps/api/src/lib/agent-commands.ts` L99-103 |
| 3 | 证书有两条并行路径（Caddy auto / ACME 账户 + 手动签发），概念混淆 | `docs/cf-dns.md` §1 与 `routes/certs.ts` |
| 4 | 配置分散在四个入口（DNS 账户 / 域名 / 证书 / 隧道），彼此依赖关系不直观 | 设置页现有分段 |

注：`docs/cf-dns.md` 写「安装命令自动带 `--tls-cn`，证书由 Caddy 自动申请」，与 L2 代码不符，本提案一并修正。

## 2. 目标与非目标

**目标**

1. 建立严格三级层级：账户 → 域名（zone）→ 解析记录；证书挂在域名上。
2. 两个入口、单一数据源：设置页是唯一管理面，添加 VM 是场景化消费入口。
3. 添加 VM 时可直接输入域名，不再被「必须先有记录」挡住。
4. 证书默认自动（Caddy auto），ACME 账户降级为高级选项。
5. 后续管理位置明确：全局域名列表 + 节点详情只读卡片 + 全局证书库。

**非目标**

- 不做全部 DNS 服务商的记录 CRUD 适配（P2 之后按需增加，未接的走手动记录兜底）。
- 不替换 Caddy，不引入 lego/libdns（与 Agent 纯标准库约束冲突）。
- 不改变 Tunnel 与 IP 直连的既有语义与安全模型。

## 3. 方案对比

| 方案 | 做法 | 优点 | 缺点 |
|---|---|---|---|
| A 全收敛到设置页 | 添加 VM 时只允许选，不允许建 | 管理面单一、实现最小 | 第一次加 VM 被迫跳走，流程断裂；新用户卡死 |
| B 全放到添加 VM | 所有域名/记录都在加 VM 时建 | 场景连贯 | 没有集中管理视图，批量维护困难 |
| **C 双入口单管理（推荐）** | 设置页做全量管理；加 VM 只做选择或最小新建，写同一份数据 | 两个场景都顺，数据不漂移 | 需严格约束入口 B 不做管理，组件必须复用 |

## 4. 信息架构与规则

```
账户（provider + 凭据）
 └── 域名 zone（可勾选托管）
      └── 解析记录（A / AAAA / CNAME / TXT，可绑定 0 或 1 个节点）
           └── 证书状态（归属域名，不归属节点）
```

**入口职责**

| | 入口 A：设置 → 域名与证书 | 入口 B：添加 VM → 域名步骤 |
|---|---|---|
| 定位 | 唯一管理面 | 场景化消费 |
| 允许 | 账户增删改、域名勾选/取消、记录增删改、证书查看/重签 | 选已有域名；就地最小新建（选账户 → 勾 zone → 填子域），建完自动选中 |
| 禁止 | — | 改账户凭据、删域名、动其他记录、出现第二套管理 UI |

**添加 VM 的三种状态**

| 状态 | 交互 |
|---|---|
| 已有账户 + 域名 | 按账户分组的下拉直接选，带证书状态标记 |
| 有账户、域名未勾选 | 就地打开「添加域名」（同截图 2 的弹窗），完成后自动选中，不跳出 |
| 无账户 | 引导去入口 A 添加；同时提供「跳过域名，先建节点」（已拍板：允许） |

**管理位置**

| 看什么 | 在哪 |
|---|---|
| 全部账户 / 域名 / 记录 | 设置 → 域名与证书（账户树 → 域名列表 → 记录抽屉） |
| 单个 VM 的域名 | 节点详情 → 域名卡片（只读 + 「去管理」跳转） |
| 全部证书 | 全局证书库；域名详情显示该域证书状态与到期 |
| 证书怎么签 | 默认跟随域名（Caddy auto）；指定 CA/算法时才用 ACME 账户 |

**数据规则**

| 规则 | 内容 |
|---|---|
| R1 记录绑定 | 一条记录最多绑定 1 个节点；被占用的记录在入口 B 置灰 |
| R2 删除联动 | 删除节点默认联动删除绑定记录（可取消） |
| R3 证书归属 | 证书归属域名，不归属节点；换域名不带走证书 |
| R4 账户停用 | 只影响新选择，已绑定节点与已签证书不受影响 |
| R5 唯一性 | 同域名下「同名 + 同类型」记录唯一 |

## 5. 三种接入方式共存

| 接入 | 域名是否必需 | 证书 | 说明 |
|---|---|---|---|
| IP 直连 | 否 | 可选（受信证书装在 Agent） | 保持现状；可选代建 DNS 记录 |
| 域名 HTTPS | 是 | Caddy auto（默认） | 本提案主路径 |
| CF Tunnel | 是（CF 域） | 由 CF 边缘托管 | 不建本地证书，不参与 Caddy auto |

Tunnel 与直连只是「域名步骤」的不同分支，域名实体与记录规则共用。

## 6. 数据模型与接口

| 项 | 处理 |
|---|---|
| 账户 / zone | 沿用 `settings.cf_dns_accounts` JSON，扩展 `provider` 与凭据字段；**P1 不新增表、不迁移** |
| 解析记录 | 沿用现有 managed records 结构，补 `recordId` 稳定性与 `boundNodeId` |
| 证书 | `certificates` 表不变（`source_node_id` 保留），不新增迁移 |
| 新增 API | `GET /dns/providers`（provider 元数据）、`POST /dns/resolve-check`（解析是否生效）；先在 `packages/contracts` 定义 |
| 改动 API | `POST /nodes` 允许 `domain` 模式不带 zoneId/recordId；`cf-dns` 端点增加 provider 维度但不破坏旧字段 |

## 9. 风险

1. **组件漂移**：两个入口若各写一套表单，必然分叉。约束：入口 B 只能 import 入口 A 的组件，不允许复制。
2. **凭据安全**：provider 凭据仍走 `MASTER_ENC_KEY` 加密；acme.sh 会把凭据明文写入 `~/.acme.sh/account.conf`，必须 700/600 且不进备份。
3. **范围膨胀**：P4 涉及节点创建后的站点编排，失败需可回滚；若复杂度超预期，P4 可单独再拆。
4. **文档漂移**：`--tls-cn` 描述必须随 P1 一起修正，否则会继续误导。
