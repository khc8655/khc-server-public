- **结论**：ADR-0010 已拍板「可见时 10s 快照轮询 / 隐藏即停」，改协议须新 ADR 取代或修订 ADR-0010 并动契约 + 双端 + 前端（红线 1 方案确认门禁）；当前无明确痛点、无需求，不做。

#### P2 隧道实现 → 不做（与 ADR-0012 冲突）
- Cloudflared 集成完整实现
- 隧道健康检查
- 自动降级与恢复
- **结论**：方案 B 与只读健康检查（`POST /nodes/probe`、530 诊断映射）已具备；「自动降级与恢复」与 ADR-0012「三种并列方案、节点选定其一、失败即报错、无跨方案回退」直接冲突，须推翻刚拍板的 ADR，方向相反，不做。

### 3.7 `workers_dev = true`
- **⚠️ 2026-11-07 已回滚：当前为 `workers_dev = true`，该项在现有拓扑下不可执行。**
- **回滚原因（实测）**：生产入口 `https://panel.example.com` 不是 Cloudflare Workers 自定义域名，而是第三方边缘 —— `CNAME <edge-host> → 203.0.113.16`（`server: Edge/1.1.35`），其**回源 Host 就是 `<worker-name>.<account>.workers.dev`**（`curl https://panel.example.com/cdn-cgi/trace` 返回 `h=<worker-name>.<account>.workers.dev`；直连该 workers.dev 域名返回与站点完全相同的 `404 / error code: 1042`）。置 `false` 等于关掉生产入口的源站，整站（`/`、`/api/v1/health`、`/agent/*`）全部 404。
- **已补的两道门**（`.github/workflows/ci.yml`）：部署前「Guard deploy topology」用 `/cdn-cgi/trace` 实测源站并与配置交叉校验，冲突即阻断；部署后「Verify production entry」先判整站健康再判包一致性，避免整站 404 被报成「包 sha 不一致」。`preview_urls = true` 保留。
- **后续正确做法（需主人操作）**：给 Worker 挂一个真正的 Cloudflare 自定义域名（如 `panel-alt.example.com`，`example.com` 的 NS 已在 Cloudflare）→ 把第三方边缘的源站改到该域名 → 才能把 `workers_dev` 置 `false`。
- **原始诉求**: 生产关闭 `.workers.dev`，避免绕过自定义域名/WAF 直接访问。
- 详见 `docs/auto-deploy.md`「事故记录 2026-11-07」、`docs/verification/2026-11-07/incident-workers-dev-as-origin.md`。

### 3.8 接入方案化改造（去掉跨方案回退，2026-11-06 新增）
- **✅ 2026-11-07 已落地**：按 ADR-0012 完成方案化改造——`orderedRoutes()` 只返回选定方案的**单一**目标，删除跨路由 `continue` 重试与 `onRouteSuccess` 自动回写 `preferred_route`，失败即抛明确错误、不换路、不改写配置；**同方案内 `fetch` → TCP 双通道回退保留**（属实现细节）。改动文件：`apps/api/src/lib/node-client.ts`、`apps/api/src/index.ts`、`docs/engineering/adr/ADR-0012-connection-scheme-selection.md`。
