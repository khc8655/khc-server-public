# UI 规范与实现一致性审计（2026-11-08）

> 状态：审计记录（非权威，不作为开发依据；结论需主人拍板后才转成规范修订） ｜ 适用范围：`apps/web/src` 全部页面 + `docs/ui-redesign/` 两份现行规范 ｜ 最后核验：2026-11-08 ｜ 关联：[ui-guidelines.md](ui-guidelines.md)、[page-specs.md](page-specs.md)、[tokens.css](../../apps/web/src/styles/tokens.css)、AGENTS.md §6.4

## 0. 结论

规范本身写得细，但**已与实现脱节**，而且缺少"防漂移"机制。后续功能不是没读规范，而是规范没给出这些场景的答案，于是每个功能各自补了一套。

1. **规范与实现直接冲突 3 处（P0）**：自动探测、状态词、Segmented 数量上限。规范目前在关键行为上是错的，继续照做会改坏产品。
2. **规范引用链断裂**：前端 20+ 处注释仍引用已归档的 `ui-spec §4.x`；`registry/routes.ts` 还在用已废弃的 T1–T5，且其中的 `routes` 数组没有任何调用方。
3. **"每页一个主操作 / 一个抽屉 / 一个详情入口"没有机制保障**：35 个 `<Drawer>`、41 个 `Dialog/ConfirmAction`、70 个 `variant="primary"`，全靠各页 `useState` 手工互斥。
4. **失败反馈普遍走 Toast**（至少 12 处），而 `Toast` 没有错误态、`role="status"`，视觉上与成功完全一样。
5. **设计系统有硬缺口**：徽标对比度 4.05/4.23 不达 4.5:1；抽屉打开不锁页面滚动；图标尺寸 14/16/20 大量绕过令牌；响应式出现规范外的 900/768/640 断点。
6. **文案层在漂移**：47 处 JSX 硬编码中文，术语表里的禁用词仍在字典里被使用（"未知""不可达""应用发布""应用配置""域名与证书"）。

总体判断：**页面骨架（A/B/C/D/E）落地得不错，问题集中在"规范过期 + 缺机制 + 长尾文案/无障碍"**。建议先修规范与机制，再做页面清理，否则清理完还会再漂。

## 2. P0：规范与实现已经互相打架

### 2.1 自动探测：三份文档说"禁止"，代码默认执行

| 文档 | 原文 | 位置 |
|---|---|---|
| ui-guidelines | "**不做自动写/探测**：打开页面只允许读取既有列表/快照；不自动 probe、apply、删除" | [ui-guidelines.md](ui-guidelines.md#L290) |
| ui-guidelines PR 清单 | "打开页面不自动 probe/apply/删除" | [ui-guidelines.md](ui-guidelines.md#L371) |
| page-specs | "**打开页面不探测**……无自动重试、无常驻轮询" | [page-specs.md](page-specs.md#L76) |
| ADR-0009 | "打开 `/hubs`：不自动探测；点 [刷新状态] 才 1 + N" | [ADR-0009](../engineering/adr/ADR-0009-ops-data-live-only.md#L61) |

实现（2026-11-07 产品决策）：`useHubProbe` 挂载即探测，15 秒 TTL 复用，概览与列表共用；注释明确写"打开页面就应该探测".

- [useHubProbe.ts](../../apps/web/src/data/useHubProbe.ts#L126-L129)
- [HubsPage.tsx](../../apps/web/src/pages/HubsPage.tsx#L48-L53)

**影响**：规范现在是"错的"，新 Agent 按规范做会退回旧行为；ADR 也没有记录这次决策变更。

**建议**：把决策补成 ADR-0014（或修订 ADR-0009 状态），并在 ui-guidelines 新增"自动加载/探测策略"一节的明确边界：

- 打开页面允许 1 次只读批量探测（`POST /nodes/probe`），15s TTL，不轮询、不逐台 fan-out；
- 写操作、apply、删除仍必须显式触发；
- 失败只提示，不自动重试；状态落"未知"并给出重试入口。

### 2.2 状态词：文档只有"未探测"，实现有"探测中/未知"

- 规范允许的状态词：在线 / 离线 / 未探测（[ui-guidelines.md](ui-guidelines.md#L187)）。
- 实现：探测中… / 在线 / 离线 / 未知（[useHubProbe.ts](../../apps/web/src/data/useHubProbe.ts#L54-L63)），且 2026-11-07 实测后**产品已明确取消"未探测"**（[hubsStatus.smoke.test.tsx](../../apps/web/src/pages/hubsStatus.smoke.test.tsx#L12-L13)）。
- 同时 page-specs 的概览指标仍写"未探测节点数"（[page-specs.md](page-specs.md#L60)），实现已换成"最后探测时间"（[OverviewPage.tsx](../../apps/web/src/pages/OverviewPage.tsx#L116-L120)）。

**建议**：术语表增加"探测中…"，并写明"未知"只用于探测请求整体失败；同步 page-specs §1.2/§1.3。

### 2.3 Segmented ≤5 与"设置页 6 段"自相矛盾

- ui-guidelines："Segmented 用于页内互斥分段（**≤5 项**）"（[ui-guidelines.md](ui-guidelines.md#L266)）。
- page-specs：`/settings` 明确要求 6 段：证书库 | 域名 | 隧道 | 应用目录 | SSH 公钥 | 系统变量（[page-specs.md](page-specs.md#L92)）。
- 实现：6 段（[SettingsPage.tsx](../../apps/web/src/pages/SettingsPage.tsx#L206-L216)）。

**风险**：390 宽度下 `.ui-seg` 是 `inline-flex + nowrap`，无换行/滚动策略（[ui.css](../../apps/web/src/ui/ui.css#L1073-L1091)），6 段总宽接近甚至超过 366px 可用宽度，**疑似**导致截断或横向溢出，需实测。

**建议**：二选一并在规范里写死——(a) 上限改为 6，且 Segmented 支持横向滚动并保证首尾可达；(b) 设置页拆成"全局设置 + 域名与证书"两个导航项。推荐 (a)，改动小。

### 2.4 前端注释仍指向已归档规范

20+ 处注释写 `ui-spec §4.x` / `T1–T5`，而 `ui-spec` 已归档、现行文档只有 A/B/C/D/E/L 与 §8.x：

- `registry/routes.ts` 的 `PageTemplate = 'T1' | 'T2' | 'T3' | 'T4' | 'T5'`（[routes.ts](../../apps/web/src/registry/routes.ts#L9-L31)）
- `ui/table.tsx`、`ui/overlays.tsx`、`ui/forms.tsx`、`ui/tabs.tsx`、`patterns/*` 等 18 个文件

**影响**：AGENTS.md §9c 规定 archive 文档不得作为开发依据，但代码注释正在把它当依据。新 Agent 会被引到错误的规范版本。

**建议**：一次性把注释里的 `ui-spec §4.x` 映射到 `ui-guidelines §8.x`，或统一改成"见 ui-guidelines §8.x"。

### 2.5 `registry/routes.ts` 的 `routes` 数组是死代码

全仓只有 `paths`、`matchHubPath`、`sectionTitleKey`、`hubSections` 被引用；`routes` 数组（含 `primary` 声明）**没有任何调用方**。而 PR 自检清单要求"新页面登记路由总表"，实际登记进了一个没人读的结构。

**建议**：要么让 `router.tsx`/导航从 `routes` 派生（真正成为单一来源），要么删除 `routes` 数组与 `PageTemplate`，只保留 `paths`；不要让"已登记"变成假安全感。

## 4. P1/P2：设计系统与无障碍缺口

### 4.1 颜色对比度不达标（实测计算）

| 组合 | 对比度 | 结论 |
|---|---|---|
| `--accent` #2F6BFF on `--accent-soft` #EEF3FF（info 徽标） | **4.05** | 12px 文本不达 4.5:1 |
| `--danger` #DC2626 on `--danger-soft` #FDECEC（danger 徽标） | **4.23** | 不达 4.5:1 |
| `--text-3` #71717A on `--surface-2` #F4F4F5（卡片内辅助字） | **4.40** | 不达 4.5:1 |
| `--accent` on `#FFFFFF`（链接/主色文本） | 4.50 | 刚好压线 |

证据：[ui.css](../../apps/web/src/ui/ui.css#L226-L241)、[tokens.css](../../apps/web/src/styles/tokens.css#L7-L11)。规范没有任何对比度阈值（§8.1 只讲语义），所以这类问题不会被发现。

**建议**：tokens 微调（info 前景降到 `#2457D6` 一类，danger-soft 前景加深），并在 ui-guidelines 增加"文本 ≥4.5:1、非文本 ≥3:1、深色单独验"的硬指标。

### 4.2 抽屉/对话框打开时不锁页面滚动

`Drawer` 只处理 Esc 与焦点，没有 `document.body` 滚动锁；CSS 也没有 `:has()`/body class。规范 §8.3 明确要求"抽屉打开时锁定页面滚动"。证据：[overlays.tsx](../../apps/web/src/ui/overlays.tsx#L91-L103)、[ui.css](../../apps/web/src/ui/ui.css#L1601-L1621)。

### 4.3 图标尺寸绕过令牌

- 规范令牌是 `--size-icon-sm/md/lg/xl`（16/22/32/40）。
- 代码里 `size={14}` 出现 28 次，`size={16}` 9 次，`size={20}` 2 次（`Icon` 的 `size` 是数字字面量）。图标 glyph 尺寸没有对应令牌。

**建议**：新增 `--size-glyph-sm/md/lg`（14/16/20）或统一到 16/22，并在规范里写明"图标 glyph 与图标容器是两套令牌"。

### 4.4 响应式断点超出规范

规范只定义 ≥1024 / 640–1023 / ≤639（§8.13）。`ui.css` 另有：

- `@media (max-width: 900px)`（两处，hub-cards / hub-grid）
- `@media (max-width: 768px)`（triage strip）
- `@media (max-width: 640px)`（hub telemetry）

证据：[ui.css](../../apps/web/src/ui/ui.css#L3360)、[ui.css](../../apps/web/src/ui/ui.css#L4041-L4159)。

**影响**：900/768 断点既没有验收宽度，也没有截图要求，容易出现"三个断点之间"的布局空档。

### 4.5 组件清单不完整

`ui-guidelines §8.11` 只登记了约 20 个组件；实际 `ui/` 还有 `PageHeader`、`MenuButton`、`Tag`、`SyncStatus`、`ScopeChip`、`Stepper`、`Steps`、`Log`、`Command`、`ToastHost` 等，`patterns/` 还有 `TaskView`、`TodoChips`、`AdvancedSection`。规范没有"新增组件必须登记"的流程，导致同类需求各写一份。

### 4.6 空态动作与页头主操作重复

规范同时要求"页头唯一主操作"和"空态唯一引导按钮"，但没有规定两者是否可以是同一动作、是否应同时出现。实现里普遍是同一动作出现两次（如 [HubsPage.tsx](../../apps/web/src/pages/HubsPage.tsx#L331-L386)、[caddy/page.tsx](../../apps/web/src/apps/caddy/page.tsx#L1528-L1605)）。

**建议**：规范明确——空态时页头主操作保留但降级为 default，或空态只保留说明不给按钮；二选一全站统一。

## 6. 规范补丁清单（建议直接改文档）

### P0（先改规范，避免继续错）

1. **新增 §8.15「自动加载与探测策略」**：明确打开页面允许的 1 次只读探测、TTL、失败态、禁止项；同时修订 §8.12 与 §10 清单。
2. **修订 page-specs §1.2 / §1.3**：状态词改为"探测中… / 在线 / 离线 / 未知"，概览第二个指标改为"最后探测"。
3. **修订 §8.11 Segmented 上限**：≤6，并规定 ≥5 项时必须可横向滚动、首尾可达；或拆分 `/settings`。
4. **术语表补 3 个词**：探测中…、未知（仅探测请求失败）、应用更改（apply-only）。
5. **补 ADR**：记录 2026-11-07 "打开即探测" 决策，并标注 ADR-0009 的对应条目被取代。

### P1（补规范空白）

6. **新增 §8.16「一页多表」**：主表 + 辅助表的顺序、间距、是否允许辅助表行点击进第二个抽屉、折叠规则（当前 sites 页有 3 张表、wireguard 2 张、host-ops 4 段）。

## 8. 防回归：把规范变成可执行检查

这是本次审计最建议补的一环。现在所有规则都靠人眼，后续功能必然继续漂。

建议加一个轻量脚本（不引入新依赖，Node 标准库即可），在 `./scripts/verify.sh` 里跑：

1. **禁用词扫描**：`未知错误`、`确定要`、`提交`、`应用发布`、`域名与证书`、`客户端`、`不可达`（白名单除外）；扫 `i18n/zh.ts` + TSX 文本节点。
2. **硬编码检查**：TSX 中出现 `#[0-9a-f]{3,8}`、`fontSize:`、`style={{`（白名单：动态定位/骨架宽高）。
3. **规范引用检查**：禁止 `ui-spec §`、`T1|T2|T3|T4|T5` 出现在 `apps/web/src` 注释里。
4. **结构检查**：每个页面文件 `variant="primary"` 静态出现次数 ≤ 2（页头 + 抽屉）；`<Drawer` 每个页面文件 ≤ 1（或改用统一 `PageDrawer` 后 ≤ 1）。
5. **断点白名单**：`ui.css` 只允许 `1023/639/640`（或新规范定稿后的白名单）。
6. **令牌完整性**：`var(--*)` 必须全部在 `tokens.css` 定义；`tokens.css` 不得有未使用令牌（当前 `--accent-hover` 未使用）。
7. **对比度测试**（可选）：用纯 JS 计算 badge 前景/背景组合，低于 4.5 直接失败。

更彻底的做法是把 `<Drawer>` 收敛成页面级单例（`PageDrawerProvider`），从组件层保证"同一时刻最多一个"，而不是靠 20 个页面各自记得互斥。
