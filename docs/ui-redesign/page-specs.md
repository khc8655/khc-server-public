## 1. 全局层页面

### 1.0 全局外壳顶栏任务入口（所有页面共用，2026-11-12 B3）

- **节点上下文（`/hubs/:id/**`）**：顶栏面包屑右侧显示「任务」入口；有 `pending/running` 任务时显示「N 个任务进行中」并带状态点。点击打开 shell 级只读任务抽屉（不新增页面）。
- **全局页（`/`、`/hubs`、`/settings`）**：**不渲染**任务入口。没有节点上下文就没有数据源，禁用按钮只会留下一个死控件。
- **抽屉四态**：有任务（状态/进度/末几行日志）· 无任务（空态）· 旧 Agent 无 `tasks` 字段（升级说明）· 离线（快照不可用说明）。
- **数据来源**：只读现有 10 秒快照的 `tasks` 字段；不新增请求、不新增轮询，10 分钟 / 60 次封顶不变；不提供任何危险动作。
- **文案口径**：入口「任务」；进行中「N 个任务进行中」；标题「任务」；副标题「随 10 秒快照更新 · 只读」。

### 1.1 `/login` 登录页（类型 L）

- **目的**：单用户（admin）认证，session cookie。
- **谁/场景**：管理员，session 过期或首次打开，频率极低。
- **首屏**：居中窄卡：产品名 + 密码输入 + [登录]。无任何导航。
- **交互范式**：单表单页，沿用 `LoginShell`。失败 = 表单内联错误（InlineError），不跳页、不弹窗。
- **操作入口**：唯一主按钮 [登录]；回车提交。
- **空态/异常**：密码错误 → 内联"密码不正确"；控制面不可达 → 内联"无法连接控制面"。
- **命名**：标题"登录"，无多余文案。

### 1.2 `/` 全局概览（类型 A · 分诊概览）

- **目的**：回答"整个集群正常吗、有没有要处理的事"。
- **谁/场景**：管理员每次进面板的第一眼，高频。
- **首屏**：
  1. 「需要处理」分诊条（仅在有问题时出现：离线节点、应用异常（展示域名与站点名）、14 天内到期证书，chip 可点直达）；
  2. 单行集群状态摘要条（`.ui-overview-strip`，仅展示节点在线 x/y 与非零应用/Peer/待办计数，「未探测节点数」已删除：探测为挂载即发，见 ADR-0014）；
  3. 节点矩阵卡：每节点一卡，按「身份 → 可用性 → 承载」三层排：
     ① 身份：名称（16/600）+ 状态徽标（在线 / 离线 · 已失联 N 天 / 探测中）；
     ② 可用性：端点（mono 弱色）+ 接入方式 chip（域名 / Tunnel / IP 直连）；
     ③ 承载：只列已安装/已配置的应用（名称 + 实装状态，最多 3 个）+ Peer/站点/转发计数 + 最后在线。
     点击进节点概况。运行态（CPU/内存/服务）**不**在概览展示，指标只在节点页由 10s 快照轮询提供（ADR-0010）。
- **卡片数据来源（2026-11-12）**：计数来自 `GET /nodes` 的 `summary`（D1 期望配置派生，零节点连接）；应用实装状态来自同一次 `POST /nodes/probe` 的 `apps`（`/state` 投影，只含名称与布尔值）。探测未覆盖（离线 / 旧 Agent）时按 `summary` 列出期望应用并显示中性「未读取」，不推断「未安装」。
- **应用状态口径**：`installed === false` 的应用**不占卡片**（与概况页「只列已配置」一致）；`running === true` → 运行中；已安装且 `running === false` → 未运行（琥珀）；已安装但 `running === null` → 未读取（中性灰）。全部应用都未安装时显示「暂无已安装应用」；探测未覆盖时才按 `summary` 列期望应用并显示「未读取」。工具型适配器（certificates / host-ops）不上卡片；node-exporter 仅在已安装时显示。
- **计数规则**：只写对象名 + 数字（`Peer N` / `站点 N` / `转发 N`）；停用站点才追加琥珀 `· N 停用`；未配置的项不渲染，全部为空时不显示计数行。**有配置行但条数为 0 时必须显示 `站点 0` / `转发 0`，不得空白**。
- **区块顺序**：分诊条 → 指标 → 节点矩阵。**不再**在页头放任何创建按钮。
- **请求预算**：打开一次 = `POST /nodes/probe` 1 次（批量轻量探测，不再逐台 fan-out）+ `GET /nodes` 1 次 + `GET /certificates` 1 次，共 3 次；有离线节点时按 60/120/240 秒最多自动复核 3 次（每次仍只 1 次批量探测），全部在线或手动「刷新状态」即停——单次打开最多 **1+3 次探测**，不做常驻轮询（ADR-0014）。
- **操作入口**：只有导航性质的"进入节点"；无写操作。
- **次要内容**：各节点明细（站点列表、Peer 列表）一律不展示，去节点页看。
- **空态**：无节点 → EmptyState「还没有节点」+ [创建节点]（跳 /hubs）。**异常**：控制面数据加载失败 → InlineError + [重试]。
- **命名**：页面标题"概览"。

### 1.3 `/hubs` 节点列表（类型 B · 列表对象）

- **目的**：节点的增删与接入（安装命令）。
- **谁/场景**：加机器、换机器、重装 Agent 时，低频。
- **首屏**：一张节点表：名称 | 状态 | 接入地址 | 最近在线 | 操作（进入节点）。页头右侧唯一主操作 [＋ 创建节点]，旁边次要操作 [刷新状态]。
- **交互范式**：B 标准 —— 行点击/行内"进入节点"进节点概况；行内第二个动作「删除节点」（L3：确认框内输入节点名解锁）。删除**总是**在删除前生成卸载脚本（控制面生成，不依赖节点在线），删除后脚本留在抽屉内可复制/下载；确认框只保留「同时删除面板代建的 DNS 记录」勾选。节点设置不再提供删除入口。创建走右侧抽屉（创建成功后在同一抽屉显示 token + 安装命令，CodeBlock + CopyButton）。
- **状态三态与刷新边界（2026-11-08）**：状态列只有 在线 / 离线 / 探测中（探测请求整体失败时显示「未知」），**不会把未探测当成离线**。打开页面即自动批量探测一次（`POST /nodes/probe`），15 秒内复用结果；页头 [刷新状态] 强制再探。**离线才自动复核**：探测出不可达节点时按 60s → 120s → 240s 最多再探 3 次，全部在线、手动刷新或离开页面即停（无常驻轮询）；停在后台后回到页面，距上次探测超过 60 秒补探一次。
- **失联标记与清理（2026-11-08）**：本次探测确认不可达、且距 `lastSeenAt` ≥1 天的节点，状态徽标显示「离线 · 已失联 N 天」，表格上方出现警告横幅「N 个节点已失联超过 1 天」+ [删除失联节点]。该按钮直接打开既有 L3 删除确认（输入节点名解锁），并沿用「删除前总生成卸载脚本 / 可勾选清理面板代建 DNS」的逻辑；不新增页面或第二种删除入口。
- **创建抽屉的接入区块（AccessForm，2026-11-07）**：统一为 `node-settings/AccessForm`，与节点设置「修改接入方式」共用同一受控表单与 `toCreatePayload()/toPatchPayload()` 纯函数。字段 = 节点名称（添加与修改都可编辑）+ 接入方式三选一：**域名（ACME）** / **Tunnel** / **IP 直连**。
  - 域名：只用现有 [Zone 下拉] + 「已有解析记录」下拉（只读拉取 A/AAAA/CNAME，不在此新建/修改 DNS）；选中记录后端口默认 443，可选 443/8443/2053/2083/2087/2096，并只读预览 `https://<记录名>[:端口]`；同名冲突/已绑定其他节点的记录置灰。
  - Tunnel：下拉选择 `/api/v1/tunnels` 的全局隧道配置；空态显示「还没有隧道配置」+ 链接到 `/settings?tab=tunnels`；选中后只读展示 `https://<hostname>` 与源站端口，不填端口。服务端按 tunnelId 推导 endpoint，并让安装命令自动注册 cloudflared。
  - IP 直连：主机/IP + 端口（默认 8880）+ 必须勾选「我确认这是明文 HTTP，仅用于内网/测试」；未勾选时保存按钮禁用并提示。
  - 旧「手填 endpoint + CF Zone/子域名 + 隧道地址 + 自签」组合已移除；安装选项只保留 system/user 安装方式与 Caddy 软件包勾选。
  - 创建成功后结果态增加 [我已完成安装]：调用 `POST /nodes/probe` 展示在线/离线，离线时给出 3 条排查提示（DNS/证书、cloudflared/隧道、防火墙放行）；探活失败不阻断抽屉关闭。**安装完成检查只含两项**：Agent 在线 + Caddy（已就绪 / 未安装 / 未运行 / 未读取，取自同一次 `/state`）；WireGuard、端口转发等按需模块不参与检查，也不催促安装。
  - **删除节点确认文案归属**：`/hubs` 行内删除的 ConfirmAction 文案明确「只删除面板中的节点记录；不会删除全局域名解析记录与隧道配置，之后可复用于其他节点」，并保留「同时删除面板代建的 DNS 记录」勾选作为额外清理。
- **次要内容**：无。
- **空态**：EmptyState + [创建节点]。**异常**：InlineError + [重试]。
- **命名**：对象统一叫"节点"（不再混用 Hub）。

### 1.4 `/settings` 全局设置（类型 B + D）

- **应用管理分段（R1，类型 D 资源库）**：数据运行时读 `/api/v1/app-manifests`。表：应用 | ID | 版本 | 运行用户 | 状态。整行点击打开编辑抽屉：应用 ID（创建时）、应用定义 JSON（mono 文本域，失焦后由 Worker 的 `.strict()` 契约校验并回显错误）、启用开关。行内动作「编辑」「删除」（L2 确认）；空态主操作 [添加应用]。新增或修改定义不需要发版。

- **目的**：管理全局 DNS 账号、域名解析、证书库、隧道、应用清单与 SSH 公钥。
- **谁/场景**：配置云厂商 DNS Token、拉取域名与管理解析记录、签发/轮换证书、维护受管应用清单，中低频。
- **首屏**：Segmented [账号 | 域名管理 | 证书库 | 隧道 | 应用管理 | SSH 公钥]，默认证书库。页头唯一主操作随分段切换（账号 → 添加凭据；域名管理/应用管理 → 卡内直接操作；证书库 → 签发证书；隧道 → 添加隧道；SSH 公钥 → 添加公钥）。路由查询参数 `?tab=accounts` / `?tab=domain` / `?tab=tunnels` 可直达；旧 `?tab=cloudflare` 映射「账号」、`?tab=domains` 映射「域名管理」、`?tab=catalog` 映射「应用管理」、`?tab=system` 映射「证书库」（不再提供「系统变量」与只读「应用目录」Tab）。
- **账号分段（S1）**：仅管 DNS Token 凭据与服务商类型（一期支持 Cloudflare，界面与模型预留腾讯云 DNSPod / 阿里云 DNS 扩展），列出账户名、状态与已启用域名数（不在卡上放「查看域名」假跳转）；API Token 使用密码掩码 + 显隐切换，仅 1 个 Zone 新建时保存后自动关闭抽屉，多 Zone 时自动切到勾选态。
- **域名管理分段（S1 + P3）**：无账号或未启用域名时引导前往「账号」勾选；已启用域名扁平列出各账号域名（记录数 / 证书有效期 / 绑定节点 / 来源账号），点「管理记录」打开唯一抽屉增改删 A/AAAA/CNAME 记录（行内确认删除，不关闭抽屉且仅刷新当前 Zone）并执行 DoH「检测解析」（语义色徽标 + 检测时间 + 公共递归缓存提示）。
- **证书库分段（B）**：证书表：名称 | 域名 | 签发方 | 同步方式 | 到期 | 来源 | 操作（导出 / 删除）。页头右侧 [＋ 签发证书] → 抽屉表单（面板 CF DNS-01 签发 / 导入 PEM / 节点自签，已移除独立「节点 ACME」模式）。到期 ≤30 天行内琥珀徽标，≤7 天红。0 证书时隐藏孤立搜索框与重复空态按钮。**证书详情抽屉（2026-11-22）**：KeyValue 之后是「续期后自动同步」乐观开关、关联节点与 [续期] / [导出] / [删除]；抽屉内点击 [删除] 采用底部行内二次确认（不叠弹窗），点击 [导出] 先关抽屉再确认。节点作用域顶部显示「节点入口（HTTPS）」卡（读 `/state` 的 `agent.tls`）。
- **隧道分段（B + D，2026-11-07）**：全局隧道配置表：名称 | 域名 | 源站端口 | Token 状态 | 更新时间；一行一条配置，行点开同一抽屉编辑。抽屉字段：名称、对外域名、源站端口（默认 8880）、Cloudflare Tunnel Token（编辑时留空 = 保留）；Token 只写不读、加密保存且不回显。删除 = 页面级 ConfirmAction（L2，说明不会删除 Cloudflare 上的 Tunnel/DNS，仍有节点引用时需先改接入方式）。面板只保存配置，不调用 Cloudflare API 创建 Tunnel。
- **SSH 公钥分段（B + D，P4）**：全局公钥表：名称 | 指纹 | 注释 | 更新时间；行点击打开重命名抽屉，行内 [删除] 走页面级 ConfirmAction（L2）。添加抽屉：名称 + OpenSSH 单行公钥（服务端校验并计算 fingerprint，重复指纹 409）。只存公钥，私钥永不进入面板；主机运维「添加公钥」对话框提供「从公钥库选择」下拉（按需读取 1 次公钥库，失败不阻塞手动粘贴）。
- **操作入口**：行内可见按钮最多 2 个，其余动作进 `⋯` 菜单；页内主操作统一收在页头。
- **空态**：证书空 → 「还没有证书」，引导由页头 [签发证书] 触发。

## 2. 节点层页面

### 2.1 `/hubs/:id` 节点概况（类型 A）

- **目的**：回答"这台节点正常吗、要处理什么"。
- **请求预算**：打开页仅 1 次聚合请求 `GET /api/v1/nodes/:id/overview`（Worker 返回 D1 投影 + 一次 `/state`，并回填 `node` 与 `/state` 共享缓存；不再额外发 `/nodes/:id`、`/state`、`/apps/*`、`/certs`）+ 独立 10s `/snapshot`。
- **首屏**：
  1. 鉴权失败/离线 Banner（离线由外壳 `HubReadOnlyNotice` 统一渲染，不重复）；
  2. 页头：节点名 + 统一接入行 `NodeAccessLine`（R5 接入方式 chip + 地址 + HTTPS/证书/明文说明 + `Agent v...`），在线态只在顶栏显示一次，去掉重复摘要与页脚；
  3. 非零指标条（R2/R3，与首页节点卡片同源）：应用在线 / Peer 在线 / 端口转发 / 证书（附「证书库（不含自动签发）」），全部离线标红「N 个离线」，全 0 整项隐藏；
  4. 「需要处理」分诊条（R4：受管 failed 单元 + 应用 502/503/504/down 异常 + 离线 Peer + 14 天内证书），系统自带单元失败不进此处；为空整条隐藏；
  5. 两列主体（左卡按需、右卡常驻）：左卡「应用/网络」（反代应用 + Peer/转发，无内容隐藏）；右卡「主机」（CPU/内存/磁盘进度条、系统/内核、运行时长、受管服务列表、系统单元失败灰色入口）。

### 2.2 `/hubs/:id/sites` 应用（类型 B + 抽屉表单）

- **目的**：管理这台节点的 Caddy 反代应用（主表只列 `kind=proxy`）、静态/跳转与节点关联证书。
- **首屏**：
  1. 动态 Segmented `[应用 | 静态与跳转（有才显示） | 证书（有才显示）]`；只有 1 个分段时隐藏切换器（R2）；
  2. 应用主表：`应用 | 访问地址（完整可点 `http(s)://域名[:端口]` + 复制按钮 + TLS 简标）| 指向目标（宽屏独立列，窄屏并入应用列第二段）| 状态（已同步 / 待应用）| 操作`；加载中先显示骨架，反代为空时显示「还没有应用」+ [添加第一个应用]（P-5）；待应用横幅主动作按钮为 [应用到节点]；搜索框支持按应用名、域名或端口过滤；
  3. 「已安装的托管应用」卡片仅在已装数量 `> 0`、加载中或报错/卸载中时展示，0 项时自动隐藏；
  4. 「本机监听端口」卡片仅在存在未发布端口（已过滤 `caddy` 自身监听端口）时渲染（R2），每行提供显式 [发布] 按钮（与行点击一致，预填进程名、节点绑定域名与避开占用的对外端口并打开 `SiteDrawer`）；下方外部配置接管卡自动过滤默认无域名占位块，页底「高级」折叠区只保留 [清空站点]；
  5. 「证书」分段展示本节点关联证书并注明「仅统计证书库中的证书，Caddy 自动签发的不计」（R6）。

- **抽屉与外部接管**：`SiteDrawer` 顶部增加实时 `对外访问预览（访问地址 → 转发目标）`，恢复「应用名称」字段以区分同域名多端口应用，默认预填节点绑定域名（`node.domain`）与推荐可用端口（自动避开 Agent 端口、本机上游端口及同域名已占端口），提供「与本机应用/Agent 撞端口」内联报错 + [改用推荐端口] 一键切换，以及 `.test`/`.local`/IP 自动 TLS 警告 + [改用节点域名]；保留精简字段集与抽屉内直接保存生效/失败回滚 D1、不叠 Dialog；独立 `InstallAndPublishDrawer` 三步向导同样默认预填节点域名与非冲突端口，按应用 ID 命名站点以支持同域名多端口并存；Caddy 服务状态抽屉收在页头次操作，安装由组件 capabilities 驱动（L2）。
- **命名**：页面标题「应用」；类型：反代 / 静态 / 重定向。

### 2.3 `/hubs/:id/apps/:app` 应用详情（类型 C + D）

- **目的**：单个扩展应用的配置、变更与应用。
- **谁/场景**：装了外部适配器（当前仅 node-exporter）后调配置，低频。
- **首屏**：页头（应用名 + 版本 + 状态徽标 + [保存并生效]）+ Tabs [配置 | 变更 | 任务 | 历史]。

### 2.4 `/hubs/:id/wireguard` 网络（类型 B + 抽屉表单 + E 抽屉）

- **目的**：管理 Peer（WireGuard 客户端）与端口转发。装了 WireGuard（`mode=wg`）或存在转发规则（`forwards > 0`）时顶部导航才出现「网络」Tab。
- **独立运行与零 Peer 文案**：当节点处于纯网关模式且尚无任何 Peer（`caddyMode && peers === 0`）时，隐藏 Peer 表格、按钮、横幅与计数，页面不出现「Peer / WireGuard」字样；`ForwardsCard`（端口转发）不受 WireGuard 模式锁死限制，独立管理。
- **谁/场景**：加手机/电脑进内网、开端口转发，中频。
- **首屏**：
  1. Peer 表：名称 | 隧道地址 | 状态（在线/空闲/已停用）| 最近握手 | 操作（导出配置 · 运维）。页头右侧：[接口设置]（次操作抽屉：接口名固定 khc0、监听端口/MTU/地址段）+ [＋ 添加 Peer]（主操作）。
  2. 下方「端口转发」卡：表（名称 | 监听 | 目标 | 协议 | 状态）+ 卡头右侧 [＋ 添加转发]；有待生效变更时卡上方 Banner [应用更改]。
- **Peer 抽屉（新建/编辑）**：新建保存成功后**同一抽屉**直接显示二维码 + .conf 下载（替代现状"保存后回列表再找导出"）。编辑 Tab：基本信息 / 高级（keepalive、AllowedIPs）。
- **行内「运维」**：打开 Peer 主机运维抽屉（进程 / 防火墙 / SSH 公钥，沿用 PeerOpsPanel 内容，收敛为抽屉内 Tabs）——吸收原 `/peers` 页全部功能。
- **节点栏连接指示**（2026-11-18，全站）：三态「在线 / 离线 / 探测中」；点开列出全部数据统一经控制面的通道说明（指标 10s 快照 / 主机运维 / 服务清单）。
- **次要内容**：无损换钥与跨节点迁移收进 Peer 抽屉的"高级"区；接口设置在页头次操作。
- **跨节点迁移（2026-11-07）**：Peer 抽屉「高级」区 [迁移到其他节点] → 先关闭 Peer 抽屉，再打开全页唯一迁移抽屉（目标节点下拉，排除当前节点与离线节点）。目标节点未配置内网穿透 / 处于纯网关模式 / 未配置公网地址时，[开始迁移] 禁用并给出原因；有未应用改动时提示会一并应用。执行流程：在目标节点现场生成新密钥（不复用源节点密钥）→ 保存并应用目标节点配置 → 输出覆盖客户端 `/etc/wireguard/khc0.conf` 的一键脚本（CodeBlock + 下载）。源节点 Peer 不自动删除，需人工确认设备已切换后再删。
- **空态**：无 Peer → EmptyState + [添加 Peer]；无转发 → 卡内 EmptyState 一行 + [添加转发]。**异常**：WG 未启用 → 整页替换为启用引导卡（现状已有"未启用卡"，保留并上移为唯一内容）。wireguard-tools 未安装 → **中性**说明（灰，不红不琥珀，不催促）：保留能力驱动的 [安装 wireguard-tools]（L2 确认 + 任务状态，不轮询）；端口转发组件未就绪同样用中性说明，二者都不进「需要处理」待办。
- **命名**：页面标题"内网穿透"；对象名统一"Peer"；"WireGuard"只出现在接口设置等技术语境。

### 2.5 `/hubs/:id/ops` 主机运维（类型 E）

- **能力占位**：服务段行内"重启"已注册 `hostOps.svcRestart` 动作但恒禁用并提示"服务重启能力尚未开放"；待 Agent `svc.restart` 白名单 verb 拍板后放开。
- **空态/异常/离线**：动词报错 = 表上方 InlineError 保留数据；快照统一经控制面 `/nodes/:id/snapshot` 10s 轮询（隐藏即停、10 分钟/60 次封顶），区分 `实时快照（10s）` 与 `已停止自动刷新 · 数据截至 xx:xx`（附 [手动刷新]）；快照失败保留上一帧并提示重试；**不周期拉取 `/state`**（服务/进程等重数据只在打开工作区时取一次 `/state`）；写闸门按 `canApply`。诊断入口保留。
- **待新增后端能力**：`svc.restart` 白名单 verb（另有 `svc.logs` 只读 verb 供服务详情日志），需单独确认。
