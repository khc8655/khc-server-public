# ADR-0017: 站点表新增「后端」列（对外服务可见，纯前端推导）

- 状态：已接受（主人 2026-11-12 拍板 C：只改现有站点页，不新增路由）
- 日期：2026-11-12
- 决策者：主人
- 关联：`docs/plans/ui-ia-redesign-2026-11-12.md` §4、`docs/ui-redesign/page-specs.md`、`agent/adapters/caddy_site.py`、`agent/adapters/wireguard.py`

## 背景

主人明确：WireGuard 用于连接没有公网地址的 VM，把 VM 上的程序发布出来；端口转发用于把这类 VM 的 SSH、远程桌面转发出来；程序目前手动安装，再由 Caddy 发布。
现有站点表只能看到上游地址，看不出后端是“本机程序”还是“某台内网 VM”，VM 掉线时也看不出原因是 Peer 离线。

## 选项

| 选项 | 做法 | 利 | 弊 |
|---|---|---|---|
| A 新增节点层「对外服务」页 | 新路由，聚合网页服务与远程访问 | 一页看全 | 新增路由/侧栏/空态/390 改动面，超出本轮收益 |
| B 新增“服务”数据模型 | D1 新表或新适配器记录引用关系 | 引用明确 | 违反核心冻结，双写一致性、迁移成本 |
| **C 只改现有站点页（采用）** | 站点表新增「后端」列，按地址识别本机 / 内网 VM（带 Peer 在线）/ 内网未登记 / 外部 | 改动最小、零后端改动、零新增请求；可随时撤掉 | 远程访问仍分散在内网穿透页，不能一页看全 |

## 决策

采用 C：
1. 「后端」是**推导列**，不是数据；不新增路由、不新增 D1 表、不改写入链路。
2. 识别规则（本机 / 内网 VM / 内网未登记 / 外部 / 套接字）与状态推导写在 `apps/web/src/data/services.ts`，是唯一实现，全分支单测。
3. 数据来源只用已有查询缓存（D1 站点配置、D1 WireGuard 配置、`/state` 的 `siteHealth` 与 Peer 在线状态），**零新增请求**。
4. 术语统一为「对外服务」，不与既有「扩展应用」混用；本轮界面不出现新的页面名。
5. 托管安装、发布抽屉增强不在本 ADR 范围内。

## 影响 / 迁移 / 回滚

- 站点表新增一列；窄屏按现有 `low priority` 机制隐藏该列。
- 回滚：去掉列与纯函数即可，其他页面不受影响。

## 验证

- `services.test.ts` 覆盖识别与状态推导全部分支（含 IPv6、带 scheme 上游、多上游、Peer 停用、WireGuard 未安装时 10.x 归「外部」）。
- staging：发布一个本机程序（`127.0.0.1`）和一个 VM 程序（经 Peer），停掉 VM 的 WireGuard，确认两行「后端」列状态正确。
