# ADR-0014: 打开页面即探测节点（规范向实现看齐）

- 状态：已接受（主人 2026-11-12 拍板 A：规范向实现看齐）
- 日期：2026-11-12
- 决策者：主人
- 关联：`docs/archive/plans/ui-ia-redesign-2026-11-12.md` §2.2、`apps/web/src/data/useHubProbe.ts`、`docs/ui-redesign/page-specs.md` §1.2、`docs/ui-redesign/ui-guidelines.md` §8.12、`docs/ui-redesign/audit-2026-11-08.md`
- 不取代：ADR-0009 / ADR-0010 中关于观测通道的结论

## 背景

`page-specs.md` §1.2 与 `ui-guidelines.md` §8.12 都规定“不轮询、不自动重试”“探测与刷新必须由用户显式触发”。
实现 `useHubProbe` 是：挂载即调用一次 `POST /nodes/probe`，15 秒内复用结果；发现离线节点时按 60/120/240 秒最多自动复核 3 次。
代码注释写明这是 2026-11-07 主人的反馈（“打开页面就应该探测，不想再看到『未探测』”）。规范与实现冲突，审计（2026-11-08）已指出，但没有成文决策。

## 选项

| 选项 | 做法 | 利 | 弊 |
|---|---|---|---|
| A 规范向实现看齐（采用） | 把挂载即探测、15 秒复用、离线最多复核 3 次写进规范 | 与主人反馈一致；无代码改动；请求有上限（每次打开最多 1 + 3 次） | 离线节点存在时多 3 个 Worker 请求 |
| B 实现向规范看齐 | 去掉挂载探测，回到手动「刷新状态」 | 请求最少 | 违背 2026-11-07 反馈，重新出现“未探测” |

## 决策

采用 A：
1. 首页、节点列表挂载时探测一次（批量 `POST /nodes/probe`），15 秒内复用；
2. 有离线节点时 60/120/240 秒最多自动复核 3 次，全部在线或用户手动刷新即停；
3. **请求预算写死：每次打开最多 1 次探测 + 3 次复核 = 4 次**，不做常驻轮询；
4. 首页指标中删除“未探测节点数”；
5. 自动探测只读，不写配置；自动 apply / 删除仍然禁止。

## 影响 / 迁移 / 回滚

- 只改文档：`page-specs.md` §1.2“请求预算”与指标条，`ui-guidelines.md` §8.12“不做自动写/探测”一条改为引用本 ADR 并写明「1+3 次」上限。两份规范必须一致。
- 回滚：恢复原条文即可，代码不动。

## 验证

- `useHubProbe.test.ts` 已覆盖挂载探测与复核节奏；规范修订后与测试一致。
- `grep` 两份规范不再出现“不自动重试 / 探测必须由用户显式触发”的旧口径。
