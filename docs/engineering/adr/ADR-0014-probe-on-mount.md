# ADR-0014: 打开页面即探测节点（规范向实现看齐）

- 状态：提议
- 日期：2026-11-12
- 决策者：主人
- 关联：`docs/plans/ui-ia-redesign-2026-11-12.md` §2.2、`apps/web/src/data/useHubProbe.ts`、`docs/ui-redesign/page-specs.md` §1.2、`docs/ui-redesign/audit-2026-11-08.md`（曾建议用本编号记录自动加载策略）
- 不取代：ADR-0009 / ADR-0010 中关于观测通道的结论

## 背景

`page-specs.md` §1.2 规定首页“探测失败只在页内提示，可点「刷新状态」再探测一次。不轮询、不自动重试”。
实现 `useHubProbe` 是：挂载即调用一次 `POST /nodes/probe`，15 秒内复用结果；发现离线节点时按 60/120/240 秒最多自动复核 3 次。
代码注释写明这是 2026-11-07 主人的反馈（“打开页面就应该探测，不想再看到『未探测』”）。规范与实现冲突，审计（2026-11-08）已指出，但没有成文决策。

## 选项

| 选项 | 做法 | 利 | 弊 |
|---|---|---|---|
| A 规范向实现看齐（推荐） | 把挂载即探测、15 秒复用、离线最多复核 3 次写进规范 | 与主人反馈一致；无代码改动；请求有上限（每次打开最多 1 + 3 次） | 离线节点存在时多 3 个 Worker 请求 |
| B 实现向规范看齐 | 去掉挂载探测，回到手动「刷新状态」 | 请求最少 | 违背 2026-11-07 反馈，重新出现“未探测” |

## 决策

采用 A（待主人确认）：
1. 首页、节点列表挂载时探测一次（批量 `POST /nodes/probe`），15 秒内复用；
2. 有离线节点时 60/120/240 秒最多自动复核 3 次，全部在线或用户手动刷新即停；
3. 不做常驻轮询；页面隐藏不额外处理（复核次数有上限）；
4. 首页指标中删除“未探测节点数”。
