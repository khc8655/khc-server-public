# ADR-0018: 任务进度随 10 秒快照下发（已废弃）

- 状态：**已废弃**（主人 2026-11-12 拍板不做：维持现有手动查看与 10 分钟 / 60 次轮询上限）
- 日期：2026-11-12
- 决策者：主人
- 关联：`docs/plans/ui-ia-redesign-2026-11-12.md` §8、ADR-0010、`agent/khc/tasks.py`、`agent/khc/state.py`、`apps/web/src/data/snapshot.ts`

## 背景

长任务（安装、证书签发等）返回 taskId 后，前端各页把 taskId 存在组件 state 里，靠手动「刷新进度」读 `GET /tasks/:id`；离开页面 taskId 就丢失。
曾提议让任务摘要随 10 秒快照下发，用顶栏「任务」统一跟踪。

## 选项

| 选项 | 做法 | 利 | 弊 |
|---|---|---|---|
| A 快照携带任务摘要 | `build_snapshot` 增加 `tasks`（进行中 + 10 分钟内结束，最多 10 条，日志末 3 行）；前端统一 TaskTracker | 复用已有轮询，刷新页面后第一帧即可补全 | 触碰 `agent/khc/` 与契约（核心冻结）；有进行中任务时需放宽轮询上限，否则长任务中途断流 |
| B 恢复 SSE 推送任务 | Agent SSE 帧带任务 | 实时 | 与 ADR-0010 相反，断线语义复杂 |
| C Worker 侧任务表 + 轮询 | D1 记录任务，前端轮询 Worker | 离线也能看历史 | 需长期写 D1 与 Worker 请求；主人已否决 |

## 决策

**不采用 A/B/C，保持现状**：
1. 不改 `agent/khc/tasks.py`、`agent/khc/state.py`、`packages/contracts/`，不新增 `tasks` 字段。
2. 面板仍按需调用现有 `GET /api/v1/nodes/:id/tasks/:taskId` 查看任务；各页保留手动刷新入口。
3. **快照轮询上限写死：10 分钟 / 60 次封顶**，不因任务进行中而放宽（转发模式下 30 分钟约等于 180 次 Worker 请求，不可接受）。
4. 不恢复 SSE，不建 D1 任务表。

## 影响 / 迁移 / 回滚

- 无代码改动；本 ADR 只记录“不做”的理由，避免后续重复提案。
- 若未来要重开，需先解决轮询预算（或改为一次性查询），再单独提案。

## 验证

- 无实现验证；以本文件 + 提案 §8 的“明确不做”表为准。
